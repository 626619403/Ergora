# Supervisor follow-up handoff example

All identifiers below are explanatory symbols, not actual runs, jobs, measurements or authorization. The supervisor maintains this list separately from the current frozen review manifest and model slots. Each proposal includes its original source/candidate, reviewer input/result digest, question, dependencies, execution owner/resources, minimum acceptance and stop conditions. Execution status and evidence acceptance are separate fields.

|Order|Proposal/original binding|Question and bounded acceptance|Supervisor observation|
|---|---|---|---|
|1|Batch A from performance response R-A, input I-A, source S, candidate C; A1, A2 share original clock B and cleanup reserve|A1: matched I/O measurement by the original measurement owner, same workload/environment/quality oracle; stop at the bounded original window. A2: confirm peak allocation/reservation by the original collector, same candidate; stop if the required reader/resource is unavailable.|A1 queued; A2 queued. Neither has a job ID or execution permission from this list. Preserve original B deadline and remaining balance.|
|2|Original admission authorizes A1 and records its real attempt J-A1; A2 is still queued|Keep original claim/attempt/receipt and resource owner.|A1 running under B; A2 queued. No current review leaf, slot, candidate or clock changes.|
|3|Batch B from later resource-lifecycle response R-B, input I-B, same S/C; accepted before A2 finishes|B1: original execution owner checks cancellation/recovery, depends on a trusted terminal A1 result and required resources; acceptance needs bounded termination and identity-preserving recovery evidence, not a model assertion.|Append B1 while A1 is running and A2 queued; B1 blocked on A1. Keep R-A and R-B originals and before/after readbacks. A finished reviewer has no ongoing background producer; a later invocation needs its own authorization.|
|4|A1 loses its response; retain J-A1 original attempt and receipt identity|Reconcile only that original job/run. Absence of a response does not prove non-execution.|A1 unknown; B1 blocked. Do not resubmit A1. A2 may start only if its own dependencies/resources and B's original remaining budget allow.|
|5|Trusted original receipt arrives, or original B deadline ends|Record execution state and exact evidence acceptance independently. Unknown or failed prerequisites never pass dependants.|Update from original evidence; stop new admission at deadline and use the original cleanup owner/reserve. Leave unexecuted items queued/blocked with reasons; no new task ID renews B.|

Read back both full reviewer responses, proposal arrival order and the supervisor list before/after order 3; link every actual executed item to its original claim/attempt/job/receipt. Verify the frozen manifest, slots, original deadline/balance and candidate remain unchanged. If no checks ran, report only policy/handoff verification and retain execution/quality as unverified. Independently authorized new work must enter the existing task admission/freeze path; this list does not authorize it.
