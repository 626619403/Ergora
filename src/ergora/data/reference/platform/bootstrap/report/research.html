02

一轮怎么运行：探索并行，验收排他

协调者每轮只打开有时间线证据的 2–3 个方向。方向数与可隔离资源、代码边界匹配；不要让所有角色长期空转。

01
定义与诊断人定语义、质量与预算；计量 agent 找完整训练的关键路径。
02
并行提出与实现每个候选一个 worktree；允许改动、资源、停止条件写入任务。
03
局部筛选真实形状与调用路径；前向/反向/JVP；无收益及时关闭。
04
冻结并独立验收候选 SHA、配置、数据、初态固定；独占资源做配对完整运行。
05
组合、长程与质量在当前基线上测交互；覆盖保存/恢复、shape、缓存与训练质量。
06
人工采用与重新诊断发布新 baseline_id；保留回退；旧候选标 stale，重新 profile。
角色交付禁止越界
协调者假设排序、任务 DAG、预算、六项概览、下一步不能把未运行检查改成通过；不能改评分口径救候选
方向 agent独立 patch、最小复现、正确性自检、继续/停止建议不抢写基线、其他 worktree、共享 verifier 或 GPU 资源
计量 / 数值审计冻结代码的独立执行、原始数据、反例、结论范围不只读作者总结；不为通过而改候选或容差
基线集成人组合与当前 baseline 的真实差异、回退包、发布记录不相加单项速度；不采用过期证据
人定义训练目标和允许改变的范围；处理例外；批准基线不需要逐行读完实现，但要看证据与未覆盖部分

瓶颈排序时间线证据、可回收毫秒与不确定性

每块链接原始证据。聊天记录用于讨论，持久状态用于恢复。不同模型互评可以增加视角，权限、执行与输入来源的独立更关键。

任务状态、作业状态与恢复约定

候选：DRAFT → EXPLORING → SCREENED → INTEGRATING → CONFIRMING → READY_FOR_REVIEW → ADOPTED。任一步可 BLOCKED / REJECTED / STALE / CANCELLED。

物理作业：PLANNED → SUBMITTING → SUBMITTED → RUNNING → 终态。响应不明确进入 RECONCILING；作业成功不等于科学结论通过。

保留 experiment、attempt、run、scheduler job/group 与重启实例身份。会话恢复先查询已存在作业，不能另起同一实验。所有重试追加记录；GPU 数值失败与无收益不通过自动多跑“修复”。

03

统一计量与正确性：结果必须可比

固定配方

有效吞吐与完整更新时间

采用实际完成的全局源样本与窗口耗时；分清物理 backward、逻辑轮、GAS 和 optimizer 更新。覆盖数据、目标、反向、更新、必要通信与约定生命周期成本。

允许改配方

达到同等质量的时间

同时记录收敛样本量、任务质量和 wall clock。更高 MFU、更低显存、更快单步都只是解释指标；不能独立证明训练更有效。

门必须拿到的证据未通过时
0 · 契约完整 SHA、有效配置、容器、数据/初态、合法 shape、指标、预定阈值与资源边界补齐；不启动昂贵搜索
1 · 局部数值前向、dX/dW、JVP（若路径使用）、边界/极值/非连续输入、mask 与随机性修复或换轨；不可放宽已批准阈值
2 · 完整更新真实 optimizer 状态与更新、loss 除数、应一致的副本、分片 owner / 逻辑全局状态、实际样本与候选选择回溯语义与配置
3 · 性能确认无 profiler 的独立配对运行；同输入/增强/初态；AB/BA 顺序；固定统计计划FAIL 或 INCONCLUSIVE；保留负结果
4 · 生命周期实际触发 shape 切换、GC、保存、恢复、缓存增长、分布式扩展和预期阶段变化限制适用范围，不能宣称长期可用
5 · 训练质量预先定义的质量非劣界、代表性数据与种子；N、A 类的多步漂移与 time-to-quality拒绝采用或重新定义研究问题
6 · 当前基线组合的 exact commit / config；新鲜审查、独立证据、回退与人工决定基线变化即 stale，重新确认边际收益
默认统计协议与工具边界
  • 探索筛选与最终确认分开；确认用未用于搜索的运行/种子，避免挑中偶然赢家。
  • 同一配对的两臂从同一 checkpoint 和输入序列恢复，不能把先后连续训练当作同初态；全局完成窗口处理所有依赖 stream 与最慢参与 rank。
  • 按独立配对 run bootstrap，不把一个 run 内的 step/window 当作独立样本。默认最少 8 对、10,000 次重采样是可配置起点；功效和重复数须按噪声、收益大小和预算预定。
  • 比较器输出 PASS / FAIL / INCONCLUSIVE。PASS 只覆盖预注册的性能条件，不证明 P99、质量、收敛或全局最优。
  • 绝对门槛写清分母。例如“每 128 个全局源样本节省 10ms”不同于“每 GPU 每轮节省 10ms”。模板只是示例；调整后重新批准契约。
  • 不允许事后丢慢样本、反复抽样直到通过、复用同一 baseline run 伪装独立重复。框架/硬件升级另立比较协议，不能绕过固定环境指纹。
形式化验证适合放在哪里

把严格证明用在小而关键的边界：索引/边界条件、状态转移不变量、缓存失效、幂等提交和发布规则。对浮点 kernel，差分、梯度/JVP、随机性质测试、sanitizer 与真实训练验证仍是主线。测试和证明都不能从短 loss 曲线推出收敛。

本套件没有声称通过形式化证明；控制器验证的是字段绑定、哈希与统计可重算，训练真实性和身份由受控 runner、独立审查与审批系统负责。引入专用验证器前先测小范围投入与检错率。

04

十二个方向：按症状派任务

点开卡片即可看到输入、实施顺序、验收与交付。每张卡有可直接交给 agent 的任务文件，以及对应完整研究包。

显示 12 / 12 个方向

01 · 诊断计量与关键路径＋完整更新时间不清、指标冲突，或每轮基线更新后

输入

启动入口、最终配置、样本账本、拓扑、无 profiler 的基线

agent 实施顺序

  1. 定义逻辑轮、backward、GAS、真实更新和源样本的对应关系。
  2. 用完整完成窗口和最慢参与 rank 建立基线；保留冷启动与长尾。
  3. Nsight Systems 找依赖链与 GPU 空档；再对实际热点做 NCU。
  4. 估计关键路径可回收毫秒；仅分发最有证据的 2–3 个方向。

独立验收

计数、同步边界、profile 扰动、跨 rank 聚合、重复 run 的独立性

交付

baseline.json、timeline、FLOPs 账本、按证据排序的候选队列

Tensor Pipe 高、长同步条或累计 kernel 时间都不直接等于端到端瓶颈。
Nsight Systems ↗Nsight Compute ↗MLPerf Training ↗
02 · 数据存储、索引与主机内存＋启动 OOM、worker 内存膨胀、IO 等待或多机供数长尾

输入

数据 manifest、索引结构、各 rank/worker PSS、存储与缓存命中

agent 实施顺序

  1. 区分索引构造、文件打开、远端读取、解码和转换。
  2. 检查父进程大 Python 对象复制；试紧凑数组、只读 mmap、按需元数据与有界缓存。
  3. 按访问模式试顺序分片与分片预取；先测小文件和元数据瓶颈。
  4. 基于 CPU/NUMA 拓扑调 worker、线程、prefetch；评估共享存储的全局负载。

独立验收

采样序列、权重与分布、分片重复/遗漏、epoch 边界、恢复游标

交付

内存归属表、IO trace、索引/格式迁移方案及回退

mmap 仍占页缓存；worker 越多不保证越快；随机读取不一定适合 tar 分片。
DataLoader ↗NumPy memmap ↗WebDataset ↗FFCV ↗
03 · 数据视频解码、预处理与 H2D＋GPU 等待批次、重复 seek/解码、CPU 预处理或传输占关键路径

输入

视频路径/帧索引/PTS、动作对齐、augmentation seed、codec 与 CPU/GPU trace

agent 实施顺序

  1. 同次请求合并重复帧读取；输出复制后再做各自增强。
  2. 对照现有 CPU 解码与 TorchCodec/DALI/NVDEC 的实际支持路径。
  3. 把独立 CPU 处理移到 worker，控制 FFmpeg/OMP 线程，避免超额订阅。
  4. 用 pinned buffer、异步拷贝及明确事件依赖做有界双缓冲。

独立验收

帧顺序与时间戳、颜色/resize/mask、随机增强、源 buffer 生命周期

交付

供数分位数、decode/H2D 与训练争用记录、完整训练对照

approximate seek 可能改变帧；DALI 标准 reader 限 CFR；NVDEC 不代表整个视频管线无资源竞争。
TorchCodec ↗DALI video ↗Pinned / nonblocking ↗
04 · 数据跨目标复用与全局重排＋重复编码、重复条件投影、未消费输出或可提前工作的独立分支

输入

跨组件 DAG、每条边的样本/RNG/权重版本、最后消费者

agent 实施顺序

  1. 先找重复读取、编码、GT 评分、条件 embedding 与未消费分支。
  2. 证明语义相同后复用；合批时保留原样本拆分和 loss 权重。
  3. 缓存 key 纳入增强、mask、输入与权重版本；恢复时失效。
  4. 仅对资源互补工作试预取/多 stream，设置有界队列与 drain。

独立验收

输出、梯度、RNG 消费、候选排序、缓存失效与跨流 buffer 生命周期

交付

依赖图、消除工作量、单项/组合收益及缓存增长曲线

冻结不代表输入或随机输出不变；不同 stream 不等于独立 GPU 资源。
CUDA semantics ↗Tuning guide ↗
05 · 计算主机提交、编译与 CUDA Graph＋短 kernel 间空档、标量回读、graph break、反复编译或图池增长

输入

TORCH_TRACE、graph/recompile 日志、实际 compiled 基线、shape 序列

agent 实施顺序

  1. 移除不必要的同步与逐步日志；合并不影响异常检测的回读。
  2. 定位 graph break 与 guards；比较单层、区域、层组与整体编译。
  3. 对合法变化选 shape bucket 或局部 dynamic；保留实际输入语义。
  4. 对稳定区域捕获 CUDA Graph；测 capture 成本、重放输出生命周期和私有池。

独立验收

所有合法 shape、A→B→A 切换、RNG、旧输出、梯度/JVP、峰值与重编译次数

交付

编译地图、模式/边界对照、长期缓存曲线

fullgraph 不等于 CUDA Graph；扩大 recompile_limit 不是修复无界变化。
Compiler troubleshooting ↗CUDA Graph Trees ↗torch.compile ↗
06 · 计算形状、布局与库算子＋低效 GEMM/attention/conv、错误对齐、重复 transpose 或小调用过多

输入

真实 M/N/K、stride、地址对齐、分片后布局、attention mask 与序列分布

agent 实施顺序

  1. 在分片/包装/量化之后检查实际指针、stride 与库 kernel。
  2. 优先修存储对齐、布局转换和批量组织；避免以删模型参数修对齐。
  3. 对照 SDPA/FlashAttention、cuBLASLt/CUTLASS、cuDNN execution plan。
  4. 合法 padding 必须正确 mask；增宽/减层或截断输入进入 A 类实验。

独立验收

尾块、非连续输入、alias、mask/dropout、前向/反向/JVP、包装开销

交付

shape 覆盖矩阵、backend 命中、快慢路径和 fallback

文本 L192 不代表视频 attention 长度；更大矩阵可能提高利用率但增加总步时。
Hopper tuning ↗CUTLASS ↗FlashAttention ↗cuDNN ↗
07 · 计算定制 kernel 与融合＋真实热点仍有可解释的启动、访存或布局损耗

输入

来自训练的最小复现、当前最快库/compiled 基线、Hopper 硬件约束

agent 实施顺序

  1. 先分析量化、pack、transpose、归一化和 GEMM 周边读写。
  2. 由 KDA 或原生 Codex 执行实现→正确性→profile→修改的有界循环。
  3. 用 NCU 解释瓶颈，逐个改变 tile、流水线、向量化或融合边界。
  4. 确认后在独立隐藏 shape/数据上复核，再集成真实训练调用。

独立验收

越界/竞争、边界尺寸、非连续输入、极值、dX/dW/JVP、graph/compile 兼容

交付

可维护内核、复现、数值/性能矩阵、fallback 与保留原因

禁止硬编码测试输出、跳过计算、修改计时/检查器或只和 eager 比；KDA 不自动保证训练正确性。
KDA ↗Triton debugging ↗NCU CLI ↗
08 · 数值低精度与数值＋大矩阵/卷积占主导，或已有 FP8 的转换/缓存成本显著

输入

每条训练/冻结/候选/JVP 路径、误差预算、权重版本与 dtype 账本

agent 实施顺序

  1. 按训练 FFN、无梯度 N4、选中重算、冻结 VAE 与 JVP 分开对照。
  2. 比较 BF16、现有 FP8、torchao/TE 适用配方，计入 scale/pack/转换。
  3. 缓存按真实权重版本失效；重算不能重复推进尺度历史。
  4. 局部数值通过后做多步更新、选择翻转与长期质量验证。

独立验收

primal/tangent、dX/dW、NRMSE/极值、饱和、更新漂移、候选选择和任务质量

交付

精度覆盖表、误差预算消耗、质量与 time-to-quality 结果

H200 不直接套 Blackwell MXFP8/NVFP4；no_grad 路径仍会改变训练目标。
TE FP8 / FP4 ↗torchao training ↗Numerical accuracy ↗
09 · 容量显存、重算与优化器＋OOM、graph 池/激活峰值限制更快方案，或更新开销明显

输入

各 rank 阶段 allocated/reserved/NVML、host/PSS/pinned、活跃张量、optimizer 状态与分片

agent 实施顺序

  1. 先清理不必要生命周期；检查跨流消费者再释放或复用。
  2. 比较 region 重算、SAC 保存策略与编译分组；核对真实算子命中。
  3. 测 FP32 融合 AdamW 与 8bit 状态，包含参数同步及首次初始化。
  4. 按空间换来的完整速度选择方案；有容量证据再试分片/offload。

独立验收

RNG、所有 loss 梯度、SAC 重算计数、状态/更新与真实恢复

交付

按阶段内存账本、时间—容量 Pareto 表、组合建议

A=allocated、R=reserved、N=NVML；A 与 R 不能相加，图池不与 R 重复加。省显存不等于提速。
CUDA memory ↗Checkpoint / SAC ↗8bit optimizer ↗
10 · 分布式通信与并行策略＋暴露通信、慢 rank、并行容量或扩展效率不达标

输入

完整 collective 顺序、参数/梯度 owner、拓扑、消息尺寸、就绪/消费时间

agent 实施顺序

  1. 先分析现有 ZeRO2/DDP 的归一化、就绪顺序、桶与通信尾部。
  2. 试 bucket/连续缓冲/owner Reduce/异步统计，逐项证明语义。
  3. 结合完整更新测试 overlap、CTA 与计算争用；不只看重叠比例。
  4. 按瓶颈选择 FSDP/TP/PP/CP/EP；迁移单独分支与恢复协议。

独立验收

全局除数、零/None 梯度、多目标权重、collective 顺序、应相同的副本一致；分片按 owner 与逻辑全局状态核验

交付

通信时间线、策略与拓扑矩阵、跨机净收益

动作专家不等于 MoE；GAS 改更新频率需归 A 类；CTA=32 不是通用配置。
NCCL ↗Megatron parallelism ↗DeepSpeed ZeRO ↗
11 · 可靠性扩展、检查点与有效产出＋单机快但多机慢、GC/保存长尾、失败重跑或恢复成本高

输入

作业生命周期、全部 rank 指标、checkpoint 状态、调度/恢复耗时

agent 实施顺序

  1. 按单节点→跨节点→代表规模→生产逐级验证，分别报告强/弱扩展。
  2. 覆盖 shape 切换、GC、保存、预取 drain 和缓存增长的完整周期。
  3. 异步保存先做一致 staging，再完成写盘与完成清单；最多有界在途。
  4. 真实退出后重载继续训练；单一重试 owner 管理整组作业。

独立验收

样本/RNG/GAS/optimizer/scales 恢复、坏 checkpoint 拒绝、OOM/重试与尾延迟

交付

生产验收、恢复演练、有效训练时间占比和失效回退

短窗口绕开 GC/保存不代表生产快；GPU 独占仍可能共享 NIC/存储。
Async DCP ↗Slurm ↗Kubernetes GPU ↗ML Goodput ↗
12 · 配方算法与结构候选＋工程瓶颈已收敛，或目标明确允许改变训练配方

输入

质量目标、数据预算、评测集、允许变化与新的 FLOPs 口径

agent 实施顺序

  1. 将 GAS/有效 batch、输入裁剪、repeat、结构宽深、参数共享和近似导数独立立项。
  2. 先确认数学与训练目标变化，不混入 E 类优化榜单。
  3. 记录相同样本预算、实际更新次数与质量达到时间；运行多 seed 对照。
  4. 只有质量约束和端到端目标共同满足才建立新的配方基线。

独立验收

验证集/任务质量、学习率与训练预算公平性、FLOPs 重算、恢复兼容

交付

新配方完整协议、质量—时间—资源前沿、明确否决条件

提高 FLOPs 或扩大模型可能提高 MFU，却延长训练；不能用有限值替代质量。
MLPerf quality target ↗Megatron performance ↗TorchTitan reference ↗
没有匹配方向。清空关键词或切换“全部”。
如何避免每个方向都过度优化

从完整关键路径决定优先级；局部时间上界很小的算子通常不值得重写。先减少无用工作与同步，再比较成熟库/编译器，最后才做定制 kernel。显存优化也可以作为更快组合的容量前提，不能只按释放 GB 排序。

读研究包时核对实际框架、GPU 与版本。H200 属于 Hopper；不能把 Blackwell 专用低精度或 SM100 调优收益直接迁移过来。已启用的技术不再算新贡献；只测它在当前组合里的边际价值。

组合、停止与持续维护

先画交互表，再合并候选

标记共享的 compile 边界、重算、参数布局、FP8 缓存、通信桶、stream、buffer、CUDA Graph 池和预取队列。

低交互且有各自证据的 3–5 项可小组组合；高交互先做 baseline / A / B / AB 对照。组合退步时二分候选集，不累加单项收益。

停止规则写进任务

预定 GPU 小时、wall time、搜索范围、质量与最小收益。相同根因两次失败且没有新证据时重新诊断或停止。

达到预算或可测的 Pareto 前沿后，交付最佳已验证组合、未决问题和重开条件；不承诺全局最优。

维护对象每轮落实审查标准
参考 / 优化路径同一清晰接口；支持矩阵；可用 fallback；明确负责人新上下文 agent 能定位真实调用与失败域
配置与开关记录最终生效配置、默认值、移除日期；删除无价值的实验开关没有多份拷贝模型和互相覆盖的隐式配置
缓存与异步写出 key、权重版本、输入/RNG、所有权、最后消费者与恢复失效生命周期可测试；不依赖作者记忆
负结果库记录失败机制、适用 baseline、原始证据与重新尝试条件环境/shape/组合没变时不重复烧资源
旧仓库在本轮触及边界补特征测试、消除一处阻碍；重构与提速分 PR保持可回退；以实际修改任务衡量可维护性
基线发布唯一入口；parent generation 条件更新；不可变新版本与回退包并发采用只有一个成功；旧证据不自动续用

人可读与 agent 可维护可以兼得。保留短模块说明、稳定接口和可执行约束；把大量 trace、长日志和实验状态放证据系统。不要靠堆叠提示词、生成文档或保留所有试验分支来维护仓库。

哪些效率指标应该持续看

记录有效结论 / GPU 小时、无效和重复作业比例、候选从提出到可信结论的时间、人工介入分钟数、集成回退率、质量回退和后续维护成本。token 用量单独记录，但不作为主要成功指标。

高预算适合购买独立验收资源、足够重复与长程验证、可靠编排和高质量审查；它不能消除输入不可比、因果混杂或错误目标。

把 WAM 经验写成可执行规则

下列来自你提供的两份经验材料，作为设计输入；本次未访问私有仓库或 GPU，未独立复现其中结果。

经验或风险流程中的具体约束
逻辑轮、GAS 与更新混淆计量 agent 输出映射表；报告同时给完整 update、源样本和全局/GPU 分母。WAM 固定 microbatch 的 GAS 4→16 归 A 类；同步调整 microbatch 并保持每次更新样本与归一化时另行判断。
局部 overlap 快，完整训练慢记录并发 compute/带宽争用；只有无 profiler 的端到端确认能晋级。
布局修复夹带模型修改去 scalar bias、加宽隐藏维不自动算 E 类；优先证明存储/对齐修复的语义边界。
FP8 / 编译 / 重算互相影响先保留单项 patch，再测交互；数值检查覆盖 JVP、候选排序、重算尺度状态和权重缓存。
节省显存却更新更慢同时比较融合 FP32 与低精度 optimizer；显存释放只在它促成更优组合时计入价值。
短跑看不到周期事件GC、checkpoint、缓存增长、shape 切换和恢复必须真实触发；20 次更新不等于长程结论。
冻结模块缓存被误用cache key 包含输入、增强、mask、RNG 与权重版本；恢复和版本变更明确失效。
多 agent 污染基准或重复跑方向实验隔离；正式验收获取排他资源域；一个提交/重试负责人，响应不明先 reconcile。
不同基线 / 混合消融组合、宽度和原始配方分开比较；没有单项控制的结果标“组合证据”，不虚构独立贡献。
历史指标应如何读取

材料中原始 14B FP8 组合报告约 3228.626 ms / 逻辑轮；在相应 GAS16 定义下，4 轮 / 更新即约 12914.504 ms / 更新。该值不是另一个宽度模型的通用 baseline，也不是长期收敛速度。

BF16 等效 MFU 与按精度加权 MFU 的分母不同，必须并列说明；不能把更高的单一 MFU 当作更多有效训练工作。完整 FLOPs 账本区分训练、冻结编码、目标生成、JVP、候选评估与重算。
