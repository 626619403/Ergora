模板是填写起点。项目名、提交、性能值和示例 PASS 都需替换为真实输入与证据。先确认目标、允许路径、基线和可信命令，再启动任务。

{{TEMPLATE_CARDS}}
工作单元 DAG 与可信检查

开发 input.json 包含 goal、allowed_paths、acceptance、constraints、risk、work_units。每个单元声明唯一 id、depends_on、paths、instructions；DAG 无环、所有权明确。大型变更先固定公共契约，再实现依赖模块。

治理要求 behavior、architecture、knowledge；大改额外要求 integration、compatibility、migration-rollback。缺项或基线失败会拒绝执行。CLI 固定 task、policy、binding 和模板快照；同一 ID 不可换输入，验证与审查绑定同一 candidate SHA。

对话、CLI、A2A 如何配合

首次项目接入，把“项目接入任务”交给开发 agent，并提供仓库路径、目标与允许范围。先盘点真实命令和基线，再注册项目与创建任务。CLI 负责确定的启动、查询、批准与取消；Temporal UI 看历史；MLflow 看实验观测。

人工批准应在阅读精确计划后进行。A2A 支持其他 agent 委托任务，保持相同输入、审批与证据要求；CLI/A2A/Symphony 共享工单归属。上游 Cloud、独立身份和集群文档是扩展部署参考。
