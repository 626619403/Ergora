# 项目接入任务：交给开发 agent

读取平台 README.zh-CN.md 与项目现有 README、AGENTS、架构、CI、测试和环境说明。保留已有约定。平台共享工具与状态；业务项目拥有自己的 Git 仓库、工单和任务分支。

先盘点固定基线、实际运行/测试命令、允许路径、模块依赖、公开接口与回滚方式。提供证据，未知项明确标注；不能用示例命令、/bin/true 或固定 PASS 代替可信验收。

根据目标选择 repository-governance、large-change 或 training-optimization。复制模板到新目录，填写真实输入与工作单元 DAG，提出项目接入计划和 checks.json。大型变更需要真实集成、兼容与迁移回滚检查；训练先冻结合同、基线、指纹、质量和资源预算。

按用户授权注册和创建任务。本地 tracker 使用本地关联编号；远程工单绑定到该项目自己的 GitLab/GitHub。不要创建统一管理所有业务项目的工单仓库。

完整开发流程等待用户批准精确 plan SHA，随后 Codex 实现、命令验证和独立 Codex 新会话审查。不得代替用户进行人工批准，不得用模拟审查代替未认证的审查 agent。

导出只创建任务分支。提交、推送、MR、部署、真实训练及资源使用应符合用户当次授权。训练由操作员明确选择一个实验并确认 manifest SHA 后执行。

保留检测到的容器边界、超时、幂等、取消 fence、精确候选与证据绑定。结果不明时使用原 ID 对账，不通过改名重复有副作用的操作。

最后报告已实现、实际验证、未验证项、材料位置与下一步。不要把安装、协议测试或模型生成当作真实项目验收。
