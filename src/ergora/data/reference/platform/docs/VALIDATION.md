# 验证与维护指南

安装验证、模型认证、项目工作流与训练效果应分别确认。本指南不包含任何预设环境的验收状态。

## 安装检查

运行 bash ~/install-multi-agent-linux-deps.sh --check、agentflow doctor、uv pip check --python ~/multi-agent-platform/.venv/bin/python。核对工具版本、缺失依赖、模型配置、环境变量名、服务端口与执行边界；不要把“包已安装”当作模型账号可用。

agentflow verify 验证 Temporal、A2A 和 MLflow，并记录此次真实结果。需要重启恢复检查时使用 --restart-temporal，先确认可以短暂重启。A2A 应拒绝无 token 请求，带 token 与正确版本头的请求应到达处理器。

## 首个开发任务

使用已提交基线和真实可信检查，选择范围小、可回滚的治理任务。检查计划等待、精确 SHA 人工批准、Codex 实现、固定候选命令验证、独立 Codex 新会话审查与 REVIEW_READY。导出分支后按项目目标分支复验，再决定是否提交 MR。

测试失败、缺少 Codex 认证或缺少可信检查时应该明确阻止任务。测试夹具中的模拟模型或审批只能证明协议行为，不证明真实服务可用。

## 工单与恢复

在试点项目验证 agent-ready 等标签同步、同一请求去重、CLI/A2A/Symphony 共享所有权，以及工单权限范围。制造提交响应丢失、worker 重启、取消与旧请求重放，确认不会生成重复副作用。

NEEDS_RECONCILIATION、取消未确认或未知进程结果时保留原 ID，查 Temporal 历史、receipts、artifacts 和精确 PID。不得通过删库、新 ID 或移除守卫绕过核对。

## 首个训练实验

先以低成本、受控实验验证 manifest 绑定、基线漂移拒绝、缺失证据拒绝、精确取消与人工放行。然后在批准的硬件和数据上验证真实训练。原始性能测量、质量与恢复结论必须绑定同一候选、配置和合同，不能把安装自测当作训练加速。

## 升级与备份

先结束并确认运行中的作业，停止服务，备份工具源码、配置、state 与项目仓库。含凭据的备份仅自己可读。升级需审阅源码和版本锁差异；在途工作流可能需要版本兼容、replay 或保留旧 worker。

恢复后检查路径、权限、Secret 环境、数据完整性与容器身份，重新启动服务并完成实际检查，再启用执行。发布记录只声明本次真正完成的验证。
