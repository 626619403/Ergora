# 多入口任务所有权

Symphony bridge 与 A2A gateway 可同时部署，但必须使用同一份 `shared_ingress_db`：

```json
{"shared_ingress_db":"/srv/agent-control/ingress/leases.sqlite3"}
```

数据库按 `tracker.kind + project + issue_id` 排他：同一工单只有一个入口、一个任务修订可以继续运行。不是 TTL 锁；超时、进程退出、网络故障和取消请求都不会自动释放。任务已返回 `REVIEW_READY`，或执行器确认全部工作停止并保存可信证据后，入口才释放。

## 部署

1. 两个协调服务放在同一台可信协调主机，使用同一专用 Unix 身份与同一绝对文件路径。应用代码和模型可以在其他云端运行。
2. 父目录由协调身份拥有，禁止其他用户/组写入；数据库为 `0600`，不能在候选仓库、outbox、agent 工作区或共享产物目录中。路径不能经过符号链接。
3. 使用本地持久磁盘。不要把 SQLite 放在 NFS，也不要为多个主机各建一份同名文件。跨主机扩展需要先实现统一准入服务或共享事务数据库适配器。
4. 配置更改与数据库恢复需要维护窗口。备份整个协调状态，而不是独立恢复 A2A、Symphony 或共享所有权的一部分。缺失的所有权不会被当作已许可。

`tracker` 当前没有服务器地址，因此相同平台下、不同私有服务器上的同名项目会保守地互相阻塞。不同 GitLab/GitHub 主机应使用隔离的部署域；不要把这个限制误当成跨域统一身份。

## 现有部署升级

停止接收新任务，让旧任务完成或按现有流程核验停止并 reconcile。旧 bridge 中所有未结束的任务必须排空，再为两个入口启用共享数据库。bridge 会拒绝给已有运行猜测、补写所有权，也会拒绝在任务未结束时关闭共享模式。

旧任务格式、profile 和 Temporal 历史不变。共享模式只是新准入边界。不要通过删除记录、换数据库路径或改任务 ID 来解除未确认的运行。

## 代码接口

`dev_platform.ingress.IngressLeases` 提供：

- `acquire(tracker, owner, task_id, spec_sha256)`：初次准入时原子认领；相同身份与摘要可重复，已释放的旧修订不能重开。
- `assert_held(...)`：提交意图已经落盘后，每次运行时操作前确认原始所有权仍存在；不会创建新权限。
- `release(..., evidence_digest)`：调用者先把安全终态或可信停止证明持久化，再释放；重复调用必须使用同一证据摘要。
- `close()`：关闭连接，不释放任务所有权。

`spec_sha256` 是完整执行 spec 的 canonical JSON SHA256。原始请求字节摘要、portable compiled envelope 摘要和执行 spec 摘要具有不同含义，不能互相替换。

共享模块只核对所有权和证据引用，不能验证远端机器是否停止；这一判断必须来自执行器收据或可信操作员。审批身份、证据真实性、实际写入隔离仍由执行器和各入口控制。

## 崩溃与恢复

认领完成、入口记录尚未写入时崩溃，会留下保守的认领；同一入口可用相同任务和摘要继续准入。入口已经记录提交意图后，必须找到已有认领；不能自动重建。

安全终态先落盘、共享释放尚未完成时崩溃，入口重启后重复释放。旧任务的重复释放不会删除后来任务的所有权。未知取消、异常 Temporal 关闭或外部工作状态不明时，原任务继续占有工单，等待核验与恢复。

自动化验证包含两个入口争抢、并发认领、重启、不可变摘要、错误释放、旧释放不影响新任务、未确认取消、可信 reconcile，以及终态写入后释放失败的恢复。
