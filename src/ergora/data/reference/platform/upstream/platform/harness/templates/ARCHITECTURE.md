# 架构地图

状态：待仓库负责人填写并审查。示例层次不应直接套到所有仓库。

| 边界 | 目录 / 模块 | 负责人 | 允许依赖 | 对外契约 |
| --- | --- | --- | --- | --- |
| 领域 | `app.domain` | 待填写 | 本层 | 值对象与不变量 |
| 应用服务 | `app.service` | 待填写 | 领域、本层 | 用例接口 |
| 适配器 | `app.adapters` | 待填写 | 领域、服务、本层 | 外部系统与存储接口 |
| 程序入口 | `app.entrypoints` | 待填写 | 领域、服务、适配器、本层 | CLI / HTTP / worker |

每个新模块必须归属一层；新增层或依赖方向通过 [ADR](docs/decisions/ADR_TEMPLATE.md) 说明。
不同领域使用不同的领域包；共享模块先确定责任，不以 `utils` 作为默认归宿。

## 不变量

- 在外部输入边界校验数据；领域内部使用明确类型。
- 日志、指标和追踪带任务 / 请求关联标识，不记录密钥。
- 失败语义、重试幂等性、超时与取消语义属于契约。
- 调用图、数据库状态机等复杂关系需要额外检查；静态 import 检查只覆盖依赖方向。

## 必须补充

系统入口、主要数据流、持久化结构、租户隔离、关键用户路径和正式支持的兼容范围。
具体运行与验证命令写入 [RUNBOOK](docs/RUNBOOK.md)。
