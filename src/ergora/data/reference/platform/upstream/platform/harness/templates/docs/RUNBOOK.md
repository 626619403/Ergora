# 运行与验收

本文件必须由仓库负责人填写。模板中的占位内容不代表验收已完成。

| 项目 | 需要记录 |
| --- | --- |
| 安装 | 版本锁文件、工具链版本、可复制的命令 |
| 启动 | 每个 worktree 独立端口、数据目录和测试凭据 |
| 回归 | 单元、契约、集成、必要的 UI 场景的具体命令 |
| 故障复现 | 输入、预期、观测、最小样例、基准提交 |
| 可观测性 | 日志 / traces / metrics 查询、保留期与访问范围 |
| 证据 | 提交 SHA、环境 ID、命令、退出码、原始输出及不可变存储引用 |
| 审查 | 独立评审角色、阻塞项分级、责任人 |
| 发布 | 正式发布流水线、批准人、回滚入口 |

## 分离角色

规划者负责目标、边界和依赖图；执行者负责一个独占写入范围；验证器运行受信任检查；
审查者从原始契约与最终代码独立审查；人负责风险取舍、接口决策和发布权限。
不要求所有小改动都启动所有角色。跨模块工作才增加并行执行者。

## CI 可信边界

从已批准的基准分支加载 harness 程序、策略和债务基线。候选分支内的同名文件是待审查变更，
不得直接替换当前门禁。校验器输出应绑定确切候选 SHA，并由 CI 身份写入只读证据目录。
哈希只能校验内容一致，不能证明批准人身份；身份与权限由 CI / Git 平台强制执行。
