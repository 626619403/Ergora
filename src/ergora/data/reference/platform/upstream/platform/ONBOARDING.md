# 仓库接入任务：交给 Codex

你正在为一个已有仓库接入共享多 agent 开发平台。先读取现有 AGENTS、README、架构文档、CI、测试与构建入口；保留已有约定。只提交一个范围清晰的接入 PR，不开始业务重写，不调整生产权限。

## 先调查，后实施

1. 给出一页仓库地图：业务模块、入口、公共契约、生成代码、测试命令、部署单位、所有者和不可触碰的目录。未知项标记为未知，链接证据，不猜命令。
2. 在固定的基准提交运行团队已有检查。登记每条历史失败、可复跑命令及影响；把“原来就坏了”和“此次新增”分开。没有覆盖的受影响行为先补少量表征测试。
3. 阅读本套件 `task-types/repository-governance/README.md` 和 `harness/README.md`。把 harness 初始化到新的暂存目录，再逐文件合并适合本仓库的内容；不得覆盖已有 AGENTS。
4. 提交接入计划供负责人确认：允许路径、架构边界、可信检查命令、历史债务基线、执行器身份、人工审批与独立审查人。批准此计划后再实现。

## 接入 PR 应包含

- 短 AGENTS 导航：指向架构、开发命令、质量规则、活动计划；详细内容分文件保存。
- 版本化执行计划与决策记录；每项规则说明适用范围、所有者和核验方式。
- 能执行的架构/文档/质量检查。Python AST 扫描器只覆盖它声明的范围；其他语言接团队已有分析器，不能把未分析当成通过。
- 由受保护 CI 配置选择的验证器和历史债务基线。候选分支不得自行改验收标准或重新生成基线来通过检查。
- 独立工作区启动/销毁约定；每个任务拥有自己的端口、数据库或测试数据命名空间、日志和资源上限。
- 对应项目的 task 请求示例，填写真实基准与起始提交；演示 SHA、示例项目和空证据不得送进正式运行。
- CI 执行器接入方案：消费平台阶段请求，在受控环境运行指定角色或检查，保存原始证据，再发布绑定提交和阶段的回执。

## 先完成一个小任务

从一个文档漂移、重复工具或依赖边界问题开始；一项治理任务只治理一个有独立验收条件的问题。跑通计划、审批、实施、集成、验证、独立审查和人工合并，再增加并行度。不要为了演示而把所有模块同时交给 agent。

交付摘要只需六项：目标、影响范围、最终候选、验证证据、未解决问题、需要人决定的事项。缺执行器、凭据、证据或权限时明确阻塞，不填写模拟 PASS。

## 人与 agent 的职责

人确认目标、公共契约、风险和最终合并；agent 维护地图与计划、实现、运行检查、提交证据；可信 CI 对真实执行和身份背书；独立审查者重新读取最终代码与证据。审查结论不能仅复述作者总结。

## v1.3 契约与 A2A 接入

先读 `PORTABILITY.md`、`A2A.md`、`MIGRATION.md`。业务 task 不含 tracker 或执行引擎；维护者分别审查包、policy 和 binding，再编译冻结。普通任务不要复制平台服务。角色能力配置不能代替实际工具权限与真实 CI。

若同时使用 Symphony 与 A2A，必须配置同一协调主机上的 `shared_ingress_db`。已有任务先安全收尾再开启共享模式，不清空台账绕过阻塞。用 A2A 仅委托已准入快照；外部 agent 无权批准自己的计划。跨调用方读取、重复提交、重启和取消未确认必须纳入首轮验收。

本版未替换真实 Codex/CI 执行器；未实现的依赖保持明确阻塞。把运行配置、测试证据、候选 SHA 和剩余缺口写入接入 PR。
