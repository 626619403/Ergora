# 组合、停止与维护
1. 每个候选保留独立补丁、配置diff和真实结果；不复制一份模型实现来保留每个实验。
2. 交互图标出共享compile边界、SAC、quantization、buffer、参数layout、stream、NCCL、图池和prefetch。
3. 独立且有单项证据的3–5个候选可批量组合；高交互先测baseline/A/B/AB。端到端收益不能相加。
4. 组合变差先回退到可复现baseline，二分候选集；禁止为了保留新方案而改变样本/计时口径。
5. 长程覆盖shape轮换、GC、checkpoint、缓存增长、恢复与学习率/阶段变化；N、A类轨道另验质量与time-to-quality。
6. 发布前由基线负责人核对当前candidate、baseline、quality与回退。发布创建新baseline_id，不改写历史实验。
7. 每次发布重新profile；旧候选需重算边际收益。历史失败只有触发条件改变才重新打开。
8. 同根因两次无新证据：重新诊断或停止。达到预注册资源/时间预算、收益门槛或Pareto前沿后交接，不无限搜索。
9. 每轮清理废弃开关和重复路径；参考实现与优化实现有明确接口、支持矩阵、数值规则和fallback。
10. 汇报GPU小时/有效结论、无效或重复作业占比、人工介入时间、回退率与质量风险；不要用token数量或agent数量衡量成功。
