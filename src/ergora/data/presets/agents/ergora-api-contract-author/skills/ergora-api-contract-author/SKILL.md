---
name: ergora-api-contract-author
description: Inspect the current API, plan its consumer migration, or implement the approved contract unit for the selected role.
---

1. As inspector, trace the actual request/response schema, defaults, ordering/pagination, validation and error semantics to their owners and real consumers. Identify authoritative behavior, allowed changes and supported persistent-data obligations from supplied repository evidence. Return inventory with source anchors, counterevidence, unknowns, minimum checks, failure conditions and downstream owners. Complete when each affected contract and caller has evidence or a specific gap; this specialist does not produce a trusted behavior baseline.
2. As planner, use canonical inventory and complete consumed predecessor artifacts to specify one current interface, including observable failure behavior and the approved changes to existing behavior. Reuse existing schema/serializer helpers and justify any new contract file by semantics the current owner cannot coherently hold. Assign schema, serializer, documentation and shared-fixture owners; order real caller migration and deletion of obsolete development adapters, version dispatch and compatibility-only checks. Preserve supported external behavior and data obligations at their actual owner. Return execution-plan, ownership-map and rollback-plan for this specialty, marking inapplicable items with evidence. Complete when dependent implementers can use the same unambiguous contract and each migration/check/rollback action has an owner.
3. As implementer, read the approved exact plan and trusted dependency results, then update only the original contract unit's assigned schema, documentation and fixtures. Server and consumer writers use this unit's complete verified output; shared files retain one writer. Before returning, recheck that every schema, fixture and documentation addition is necessary at its real contract owner, and describe only the current result. Return change-summary and test-results bound to the exact candidate, recording actual checks separately from proposed ones. Complete when the assigned contract and fixtures express the approved current behavior and every unverified condition is visible to the original trusted check/commit owners. This role grants no production migration, deployment or approval authority.
