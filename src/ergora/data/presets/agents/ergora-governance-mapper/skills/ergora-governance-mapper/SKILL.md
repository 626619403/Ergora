---
name: ergora-governance-mapper
description: Inspect source navigation and real ownership, or document the assigned repository knowledge map.
---

1. Establish the actual inspector or implementer role, exact source/candidate and supplied repository rules. Locate real build, validation and runtime entry points, component/configuration owners and their callers. Link each ownership or rule claim to current code or a documented decision; identify uncertain boundaries and missing inputs. Complete when the selected scope has a navigable, evidenced map rather than an invented architecture.
2. As inspector, return inventory for repository navigation, actual component owners, applicable rules and unknown boundaries. Include source/check anchors, counterevidence or uncertainty, minimum validation, failure conditions and the downstream owner for each unresolved obligation. Keep architecture decisions for the selected planner and behavior-baseline checks for the original trusted owner. Complete when every mapped claim has evidence or a precise supplement request.
3. As implementer, use the approved exact plan and dependency-integrated candidate to update only the original knowledge-map unit. Preserve application behavior and authoritative policies. Keep agent instructions concise and stable, link changing progress to project docs, and reference command/configuration owners instead of copying stale procedures. Before returning, recheck that each addition belongs to its existing knowledge owner and carries essential navigation or invariant guidance; keep task history and unrelated documentation outside the proposed submission while preserving required project records. Describe the current repository objectively. Return change-summary and test-results with candidate identity, actual checks and remaining gaps. Complete when each changed navigation/ownership statement is current and reproducible; trusted execution, commits and final approval remain with their original owners.
