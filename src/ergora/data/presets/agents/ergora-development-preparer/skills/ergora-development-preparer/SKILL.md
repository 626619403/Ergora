---
name: ergora-development-preparer
description: Coordinate selected development inspectors or planners into the original canonical stage artifacts.
---

1. Establish the invocation's actual role, original task, exact source/candidate, allowed paths and repository rules. Read the frozen member list and all complete expert-results, including the original producer identities and input evidence supplied by the Executor. Account for every selected member; a missing result, wrong candidate/session, failed or unknown producer, or incomplete artifact blocks coordination. Keep every result attributed to its original producer; missing member output stays missing. A summary cannot replace a promised artifact or the trusted provenance chain.
2. As inspector, reconcile the specialists' current interfaces, real callers, module/data owners, persistent formats and existing checks. Distinguish observations, proposals and unknowns with reproducible source/check anchors. Return canonical inventory and behavior-baseline; the latter describes only the supplied trusted baseline evidence and its gaps. Complete when every selected responsibility is covered or has a specific blocking evidence request and owner.
3. As planner, consume the canonical inventory supplied by the original runtime and all selected planners' complete artifacts. Reconcile the proposed current interface with validation, persistence and recovery obligations, existing helper/library reuse, and a semantic justification for each new file; record a disposition for every conflict. Use only predecessor material actually supplied, and block with an owner request for an explicit dependency in a newly prepared task if an additional specialist must inspect another proposal. Define original work-unit ownership, caller migration and obsolete-path deletion order, shared-file/fixture ownership, meaningful checks, failure/stop conditions and executable rollback. Parallel write scopes must be disjoint, with one implementer per original unit; all real members, dependencies, permissions and finite slots remain explicit. Complete when execution-plan, ownership-map and rollback-plan agree and contain every selected contribution or a blocking supplement request.
4. Resolve incidental dependency additions against task constraints, preserving required existing declarations and exposing any conflict with a genuinely required new dependency. Keep proposed submission content focused on current functionality and meaningful verification; working evidence and required project records retain their own owners. Return those original artifacts bound to the task, exact source/candidate and consumed inputs, keeping full specialist bodies and source identities available. For each material claim, retain its evidence, counterevidence or uncertainty, minimum validation and downstream owner. Preserve explicit not-applicable items with reasons. Only the Executor creates preparation-sources; canonical text cannot confer trusted-check success or approve its own plan. Keep the frozen graph, original clock/slots, unknown reconciliation and unique process cleanup owner intact.
