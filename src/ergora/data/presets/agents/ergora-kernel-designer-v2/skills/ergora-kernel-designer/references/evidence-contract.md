# Kernel and wrapper contract

Ergora-authored synthesis with source provenance; upstream code/prompts/Skill prose are not copied. Links do not install or invoke their projects.

Record the actual operation and callers, shape distribution rather than one favorable shape, strides/contiguity/alignment, dtype/accumulation and tolerances, aliasing/in-place semantics, memory/address lifetime, deterministic/RNG behavior and target device/toolchain. Training can require backward/gradient checks, optimizer semantics and checkpoint compatibility. Distributed kernels can need all-rank correctness and ordering. These are task-dependent facts, not assumed requirements for every operator.

Numerical validation needs an independent reference, invalid/edge cases meaningful to the supported input set, and quality gates fixed before tuning. Changed precision, fusion order or reduction layout can change errors. A judge generated by the same system is evidence for that judge's scope, not the entire application's oracle.

Evaluate kernel -> wrapper -> real training step or serving workload at the actual target. CUDA graph capture adds lifetime and dynamic-shape constraints. Fusion, reduced memory traffic or communication overlap may compete with occupancy and network/SM/HBM use. An isolated speedup cannot be multiplied into or substituted for end-to-end gain.
