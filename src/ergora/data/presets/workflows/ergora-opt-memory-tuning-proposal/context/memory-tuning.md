# Memory capacity and allocation proposal

This Ergora-authored direction resource is an offline synthesis of the fixed sources below, not an imported upstream Skill or an installed estimator. Apply it to the supplied exact workload; unknown framework versions, tensor/state shapes and device/rank evidence stay unknown.

1. Freeze model/code/config, token and sequence regime, precision, optimizer, PEFT, mesh and device/node topology. Identify the actual failing phase and rank: construction, first optimizer update, steady step, evaluation, checkpoint or resumed next step. Complete when the owner can distinguish an observed OOM from an estimate or a proposed workload.
2. Build a capacity ledger for the hottest relevant shards: parameter storage, master weights, gradients, optimizer moments, retained activations, communication/operator workspaces, graph pools, allocator slack and external device usage. Separately request allocated/reserved/device-wide peaks and host RSS/pinned/NVMe use by rank/node with sampling windows. Reserved minus allocated alone does not establish fragmentation, and neither an average rank nor an allocator trace covers all device use. Complete when every total has units, assumptions, source identity and explicit exclusions.
3. Use a version-matched estimator only as a screening candidate. Bridge's theoretical estimator distinguishes dense/expert shards and makes optimizer/activation assumptions; it does not include all fragmentation, runtime workspaces, graphs, offload or full recompute. Do not apply its default Adam bytes/parameter to a different optimizer, low-precision state or frozen-parameter regime. Record estimate versus measured peak and the unexplained remainder. An estimate below capacity is not a run or feasibility proof.
4. Choose the smallest discriminating change from the observed phase, not a blanket memory preset. Fragmentation evidence can motivate an allocator experiment, but expandable segments can interact with NCCL user buffers and graph registration; preserve the original setting and validate the exact combination. In supported LoRA plus sequence-parallel column-linear paths, input re-gather trades retained activations for backward communication; it is not general checkpointing. Recompute and offload need their own direction contracts and version checks. Keep global/effective batch, token count and quality conditions comparable when microbatch or accumulation changes.
5. Return the ledger, ranked falsifiable hypotheses, bounded baseline/candidate comparisons, independent numerical/quality gates, exact input and measurement prerequisites, stop conditions and rollback. Request startup, steady, evaluation/checkpoint and restored-next-step evidence where applicable. A fit, no OOM or finite short-run loss does not establish throughput, training quality or production readiness. Only the original runner and owner can execute and adopt a candidate.
