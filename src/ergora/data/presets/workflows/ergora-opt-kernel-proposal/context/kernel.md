# Kernel direction: contract, native candidates and independent evaluation

Ergora-authored synthesis of the fixed R1/X2 research listed below. This resource imports no upstream prompt, code, Skill bundle or evaluator. URLs identify sources; the readonly leaf has no authority to install, fetch, compile or run them. Apply the selected branch to the supplied workload and report missing evidence explicitly.

1. **Freeze the actual task and its consumers.** Identify operation semantics, source/baseline/candidate bytes, caller and workload distribution; shapes, strides, layout/alignment, dtype/accumulation, tolerances, aliasing/in-place effects, device/stream and memory lifetime. Include zero/odd/tail sizes, masks, numerical ranges and invalid-input behavior only where the supported contract requires them. Training may require backward, parameter/input gradients, RNG and checkpoint compatibility; JVP or distributed collectives need their own explicit consumers and independent checks. A forward wrapper or a kernel named backward does not prove registration, gradients or full training. Freeze hardware, driver/compiler/runtime/DSL, compile flags, dependencies, test commands, metrics, original budget and promotion rule before tuning; preserve configurable supported inputs.

2. **Choose from measured bottlenecks and a fair baseline.** Use the project's best supported library/compiled baseline and exact workload, not an unrelated eager result or a favorable shape. Keep compilation/autotune/startup and steady-state timing separate; match synchronization, warmup, input production, rank scope, concurrency and variance. Kernel, packing/transposes/allocations, actual wrapper and whole step/service are distinct measurement levels. With an actually measured critical-path fraction f and isolated speedup s, 1/(1-f+f/s) is an idealized bound only under its fixed-work/unchanged-remainder assumptions. It is not evidence of end-to-end gain: overlap, launch costs, streams, SM/HBM contention, graph capture and fusion may change that remainder. Keep profiler overhead, dispatch/engagement and cold/hot execution explicit. Missing trace or wrapper timing remains unknown.

3. **Keep the correctness oracle independent.** Freeze reference, supported test inputs, seeds/distributions and task tolerances before search; use adversarial valid cases and multiple initializations/input sets where applicable. Candidate-generated tests and an internally calibrated judge can supplement this oracle, with their scope recorded. They cannot relax it, replace held-out checks, or select a new baseline after seeing a result. Changing precision, reduction/fusion order or math approximations also needs the task's numerical and application-quality gates. Verify wrapper dispatch, fallback, autograd registration, required gradients, stream/capture behavior and actual integration separately. Proposal text, successful import, compile, exit0 and a native PASS each establish only their own stage.

4. **KDA is an external-agent workflow reference.** At `acdd79343c5e9d0c7cb96289f26fd3f1051ce785`, NVIDIA KDA describes task definition, planning, implementation, correctness, measurement and evidence-based candidate decisions; it does not provide a single unified autonomous runtime. Use the project's original task/evidence owners rather than adding another candidate ledger. Its community wishlist is B200/B300-specific, while the general method is broader; task-local CUDA/CuTe/profiler support still needs proof. Documents/prompts use CC-BY-4.0, first-party code Apache-2.0, and submodules retain their own terms. This original synthesis does not redistribute those materials or imply a KDA process was invoked.

5. **ForgeKernel remains an original native campaign.** Ergora's installed adapter stays at `5030503d3ff71851aa34c14b9caf13ebfa9d9a78`, Linux/local delivery and the existing `kernel` owner with plan/prepare/run/status. Research head `b2c8ae8510e02c28576808910a6b8827721ab7dc` is a different snapshot, not an adapter upgrade. Preserve teacher/student planning, judge generation/calibration, native retries, campaign ID and status/unknown reconciliation. A new readonly root neither changes the native Claude protocol nor substitutes Codex for its teacher/student. A teacher-written judge or `native_finished` is candidate evidence, not external correctness, performance or adoption. Full nesting still needs complete parent material in every real internal call, permission intersection, original absolute deadline/budget, recovery and actual descendant stop evidence. Reference material conflicting with the native student's blackbox policy is an admission conflict; resolve it explicitly before execution instead of omitting mandatory ancestors or weakening native isolation. Killing an outer driver does not establish stopped model/GPU descendants; optional goal-reference paths need separate admission.

6. **KernelAgent/Fuser is more than one model call.** At `e0647170da36ef9b059ac0bd3d60103aa4ed378b`, `TritonKernelAgent.generate_kernel()` includes test generation, seeds and workers; Fuser adds subgraph extraction, parallel generation, composition and optional verification. For a supplied frozen oracle, the SDK's `generate_default_test=False` is a relevant configuration seam, not proof that all native workers are independent or integrated. Keep any extra generated tests distinguishable from the original oracle. Fuser needs actual composed-wrapper verification and fallback/engagement evidence; forward generation does not prove backward/JVP or training registration. Multiple worker/provider construction and subprocess testing paths require their own parent-material, permission and shared-budget coverage before native admission. An NCU example or a reported H100 result does not establish support/performance on a different device/toolchain.

7. **GEAK has native nested workflows and structured outcomes.** At `ec97e49ca886f8d02f8415192fdaac45d1005d2a`, the e2e JS workflow dispatches `kernel_workflow/kernel_lane.js`; standalone kernel and e2e routes are distinct invocation surfaces. Preserve its specialists, clean-workspace verification, true original baseline and native state. Evaluate structured accepted/no_gain/timeout/error/provisional outcomes and actual artifacts, not process exit alone. End-to-end claims require real kernel engagement, correct workload/server identity, warm A/B and output parity; a standalone microbenchmark cannot fill those fields. AMD device-family resources, ROCm/DSL and Claude/Codex/Node runtime versions are task-specific. An outer runtime's child kill or functional budget does not by itself prove all descendants stopped or that an Ergora parent deadline covers every nested lane; retain unknown until original-run reconciliation.

8. **AKG-AGENT is a complete search workflow, not a label for Ascend support.** The installation branch `br_agents` at `64b84b59541c134279f5d2ee0a5f35de0ec40022` has KernelGen/AdaptiveSearch/Evolve/AutoResearch, verifier/worker and session/budget state. Choose one native route and retain it. The conservative README support table and broader DSL/device enums have different scopes; check the actual task's hardware/CANN or CUDA/torch/DSL matrix rather than treating an enum or a published pass rate as compatibility or training speed. AutoResearch can quick-check, evaluate, KEEP or roll back; its calculated workflow timeout may exceed a nominal requested duration. Parent budgets and native state must survive recovery. The fixed implementation truncates context by default (15,000 chars/file, 40,000 total, separate fundamentals/Skill limits) and has separate initial, fast, diagnosis, compaction and optional reference-generation calls. Raising one limit or adding a context path does not demonstrate complete ancestor inheritance or permission enforcement at every call/tool/worker. Keep full-session integration pending until actual coverage and rejection/stop behavior are verified.

9. **robust-kbench is an evaluator/data component.** At `078f5bab29934a822268d59a4e707d449abf9b4e`, the public repository provides varied initialization/input checks, forward/backward cases and compile/test/evaluate/profile entry points. Its paper's broader translation/evolution system is not a published complete search runtime. Its filter thresholds are benchmark choices, not universal numerical or quality tolerances. Choose checks appropriate to the original task, keep external evaluation independent of the generator, and verify any required JVP explicitly. Author-reported results and eager/compile baselines cannot be combined into a hardware-independent ranking.

10. **Return a bounded handoff.** Design/profile state the exact task, source identities, observed bottleneck, hypotheses, tool-route prerequisites, finite candidate plan and missing data. Kernel consumes both complete original analyses and returns a concrete design or candidate plus wrapper, independent oracle and unsupported cases; retain candidate-only status. Measurement receives all three complete originals and actual experiment artifacts, then separates source/support readiness, correctness/quality, kernel/wrapper/end-to-end performance, total cost and adoption. Report failed/no_gain/noise/unknown unchanged, and list the smallest next checks within the original runner's budget. The original native campaign/search owns its internal loop and recovery; the trusted runner owns experiments, independent evaluation owns its results, and the project owner explicitly adopts exact candidate/evidence identities. This root runs selected readonly leaves manually; it does not schedule the graph, a native workflow or a GPU experiment.
