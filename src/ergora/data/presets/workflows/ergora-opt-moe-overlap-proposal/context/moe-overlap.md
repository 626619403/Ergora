# MoE expert-parallel overlap proposal

This Ergora-authored offline resource combines the two fixed Bridge overlap Skills below, which share the same implementation. It proposes and checks one communication direction rather than creating duplicate agents for the two source titles.

1. Freeze exact model/framework/Core/TE/torch/CUDA identities, natural routing and token distribution, dispatcher and initialized backend, precision, EP/ETP/TP/DP/CP/PP/VPP groups, rank placement, microbatch schedule, graph/recompute/shared-expert/MTP settings, baseline traces, all-rank memory and unprofiled step timing. Distinguish dispatch/combine exposed on the critical path from communication already hidden. Complete with a falsifiable workload-specific hypothesis or missing evidence; extra overlap can contend for SMs/HBM and is not automatically faster.
2. Use the selected version's full native validator instead of treating this checklist as a new validator. The cited Bridge pre-finalize checks mirror Core, which revalidates at finalize: EP>1, num_moe_experts>1, alltoall/flex, BF16 or FP16 model flags and torch>=2.6; when PP>1 a VPP value must be specified. It rejects full recompute, non-None recompute_method/recompute_num_layers, 'moe' in recompute_modules, shared-expert overlap and MTP beyond one layer. Selective recompute is not blanket permission for every module. These source constraints are necessary, not certification of arbitrary newer stacks or actual schedule activation. Complete with the effective validated candidate and any incompatible requested combination.
3. Separate plain overlap_moe_expert_parallel_comm from delay_wgrad_compute. The latter requires the former and has TE>=2.7 gates when overlapping gradient reduction or using gradient_accumulation_fusion. In the cited graph path, attention scope, or router scope with a shared expert and no shared-expert overlap, can put wgrad in graph scope: it requires TE>=2.12 and static gradient-accumulation fusion; attention scope additionally disallows linear/QKV bias. Inspect exact active scopes and address lifetimes, not just a graph flag. The performance harness's moe_a2a_overlap helper enables both overlap and delayed wgrad, so it cannot isolate plain overlap. Complete with separately frozen toggles, native validation and actual scheduling/trace evidence or unresolved activation.
4. For flex dispatch, inspect both dispatcher type and backend, the actual target selector/validator, package/API compatibility and initialized streams/buffers. The fixed selector recognizes deepep/hybridep/ncclep, keeps configuration separate from final GPU checks and rejects an unsupported final backend without silently switching. An alltoall baseline does not prove a flex path, and a helper setting shared-expert overlap false is not proof the final configuration retained it. Complete with version-matched runtime evidence or explicit missing support; baseline/overlap/dispatcher/graph changes are distinct interventions.
5. Plan an independent comparison of outputs/loss, token routing/conservation, backward gradients, delayed wgrad accumulation, optimizer updates and training quality with identical samples and predefined tolerances. Cover actual multi-rank, supported empty/skewed expert and pipeline/graph/recompute cases, plus checkpoint/RNG/data-order/next-update recovery. First compare overlap off/on with delayed wgrad false, then isolate delayed wgrad; retain the unchanged natural routing and runtime. Use paired warmed-up unprofiled end-to-end windows, all-rank memory and matching interval-union/critical-path traces, not summed kernel times or a rank0 smoke. Return finite candidates, exact original evidence, total setup/resource cost, stop/rollback and original-runner handoff; missing mandatory evidence remains request-changes/unknown, not adoption. Preserve failure/no_gain/noise and full-group cleanup responsibility.
