# Activation recomputation proposal

This is Ergora-authored synthesis of fixed source behavior. Recompute is a time/memory tradeoff; a module name or a remembered recipe is not evidence of a bottleneck, correctness or fit.

1. Freeze the exact model/attention/backend/runtime versions, precision, PEFT, mesh, effective batch/tokens, optimizer and observed peak phase/rank. Attribute activation retention separately from model/optimizer state, allocator slack, communication and graph pools. Request missing traces and state rather than inferring activation dominance from an OOM.
2. Describe a bounded candidate set in the actual version's configuration language: no recompute control, selective submodule boundaries, or full-layer uniform/block scheduling with the applicable layer counts and pipeline/virtual-stage interpretation. Full means full selected layers, not necessarily the full model. An empty selective module list is a useful control where accepted; do not declare that all versions require a nonempty list or impose a stale universal enum. Verify the selected architecture's supported labels and resolved configuration in its own runtime.
3. Explain what is replayed and when it affects the actual peak. Fused/Flash attention may already rematerialize; replaying it need not save useful memory. Whole-MoE recompute can replay routing, dispatch/combine, expert work and communication. Check dropout/RNG, mutable state, aliases, custom operations, FP8 scaling/amax, collectives and checkpoint boundaries against an independent baseline. Shape/dtype checks and finite short loss are insufficient for numerical, gradient, optimizer-update or quality parity; require the applicable oracle and tolerances from the owner.
4. Resolve interactions before recommending a combination. Saved-activation distribution and sequence parallelism have constraints in the cited Core; layer-level activation offload is a separate path with its own recompute exclusion. Selective, full and graph scopes/backends have different rules; some full-iteration configurations are exceptions to narrower graph restrictions. Preserve original configuration-validator errors and verify the exact Bridge model spec as well as Core, rather than removing a guard or promising a universal workaround. Fine-grained offload has distinct compatible/selective cases; it is not the layer-level switch.
5. Return changed boundaries/variables, memory and compute hypotheses, matched paired end-to-end step/caller measurements, all relevant rank peaks, independent correctness/quality checks and rollback. Freeze numerical/runtime/trial budgets before execution. For interacting candidates, plan baseline/A/B/A+B only when warranted; never multiply local gains. Saved memory is not automatically faster training, and a valid config is not an executed or validated candidate. Original experiment/job/checkpoint and adoption owners remain authoritative.
