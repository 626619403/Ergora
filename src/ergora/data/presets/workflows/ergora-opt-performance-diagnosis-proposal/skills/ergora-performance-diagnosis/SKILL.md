---
name: ergora-performance-diagnosis
description: Diagnose a reproducible slowdown or route supplied performance reports to a matching reader while retaining missing evidence and measurement limits.
---

Establish the observed symptom, objective, exact workload and available baseline/candidate evidence. If evidence is missing, request a feedback command that reproduces the same symptom with fixed inputs and relevant environment; explain what its result would distinguish. Keep the original reproduction when reducing the problem. A short synthetic case is useful only if it retains the observed failure.

For existing traces, snapshots or kernel reports, read [tool-routes.md](references/tool-routes.md) and select by actual input format, software version, phase and hardware. Distinguish a suggested reader from an installed, authorized tool and an actually completed read. Preserve unknowns when a report cannot answer the question.

Return evidence-backed hypotheses, competing explanations and bounded follow-up requests for the original runner. Check the original scenario again after a proposed fix. Use the role's existing measurement and independent-evaluation contract for numerical conclusions; proposal, capture, experiment execution and adoption keep their original owners and permissions.
