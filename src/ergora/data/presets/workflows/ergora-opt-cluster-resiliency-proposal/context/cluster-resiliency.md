# Cluster launch, diagnosis and recovery proposal contract

This project-authored resource plans or reviews a distributed workload from supplied evidence. It does not install Slurm/NeMo Run/NVRx, obtain an allocation, mount storage, submit or stop a job, execute a log analyzer, inject faults or restart training. Keep launch, deterministic diagnosis, model enrichment, restart recommendation and actual recovery as separate claims with their existing owners.

1. Freeze the exact workload/candidate, framework entry point and its initialization path, model/data/precision/mesh and convergence contract, container/software tuple, nodes and processes per node, hardware/topology, resource/time limits and intended checkpoint storage. Inspect supplied artifacts separately from requested specifications. State the actual site's supported submit/status/log/cancel operations and authorization; installing a client or showing a tool version grants no scheduler, container, account or quota access. If no execution access exists, return a bounded handoff and missing checks rather than claiming submission. Preserve external credential references, not values or private site wiring.
2. Choose one actual rank-spawning owner. For N nodes and R training processes per node, an entry that really uses the pinned Bridge initialize.py may use direct srun-native with N*R tasks and no second torchrun. A verified legacy launcher shape uses N tasks, one launcher per node, each spawning R workers. Do not combine R tasks per node with R children per task and accidentally create N*R*R workers. Values such as eight GPUs are examples, not invariant configuration. The pinned Slurm Skill and its copied templates disagree; inspect the actual initialization and resolved launch instead of merging them. Runtime world/rank/local-rank/master values and dense/expert groups must be checked against the chosen path and actual allocation, not inferred from a simple product of every parallelism factor.
3. Verify shared repository, data, logs, HF_HOME, UV_CACHE_DIR, NEMO_HOME and checkpoint paths on all requested nodes with consistent container-visible mappings. A path string or mount declaration does not prove visibility or persistence. Reuse site-provided container support and the accepted execution boundary; no implicit host mount authority. Dependency/cache preparation must precede training through the actual owner and budget. Do not copy destructive checkpoint-directory cleanup, online sync, credential login or arbitrary sleeps from an example into an operational recommendation. Preserve existing runs and use candidate-specific persistent outputs.
4. Bind submission to the original executor's experiment/job/task/cycle and resolved request identity. Slurm acknowledgement, NeMo Run Experiment identity and application evidence each prove different facts. Lost acknowledgement, timeout, missing status or a scheduler-visible job without application completion remain unknown; query the original identity before any retry. Keep NeMo Run's executor-specific status/detach/DAG limitations explicit. A Slurm requeue reruns the batch script; Submitit reexecution or its checkpoint hook does not automatically restore every training rank. Existing native DAG/recovery owners remain intact, with no second outer loop silently resubmitting the same job. A cancellation request needs actual job and worker terminal evidence.
5. Trace the first supported failure across supplied ranks, nodes, phases and clocks; cascading SIGTERM or NCCL timeout is not necessarily the root fault. Correlate original logs, Flight Recorder, straggler and checkpoint records, distinguishing missing ranks/events from healthy ranks. Exit codes or a textual match alone do not prove OOM, hardware fault or a safe retry. Propose discriminating checks before changing timeouts, swallowing import errors, moving nodes or weakening numerical thresholds. Retain log/source/candidate digests, uncertainty and failure/no_gain/noise/unknown outcomes; source examples are not measurements of the selected workload.
6. For NVRx Restart Agent, inspect the exact installed API and runtime support rather than assuming the package contains the studied entry. Fixed be12a1e3af7eee550abd28a67f85928ef7a9d3ab provides experimental attribution CLI/MCP, deterministic L0 evidence and same-job history/policy, optional L1 model enrichment, bounded attempts/deadline and STOP/RESTART recommendation. Analysis exit0 means analysis completion, not training recovery. Empty or degraded logs may bias toward restart; missing evidence is not restart authorization. The packaged MCP analyzes and returns results; it does not itself execute the restart. Bounded in-memory history and fixture import/export are not durable job history. Legacy source-only LogSage and packaged endpoints have different requirements. A future deterministic-only --disable-l1 tool consumer needs its own accepted invocation, original result and budget; this readonly proposal does not run it.
7. The full internal-model Restart Agent is a separate admission problem. Its native requests/routes/prompts do not by themselves carry every Ergora ancestor's complete Skill/context and permission ceiling. Before claiming that subworkflow, every actual model route/session/retry must receive the full fixed materials, expose actual sent bytes and complete reads, obey all parent file/tool/network/egress limits, and consume the original total budget/deadline. A manifest path, summary, prompt reminder, model route or MCP transport does not enforce those requirements. Keep the mode unsupported when that proof or capacity is absent; do not relabel an outer readonly call as inner native execution. Do not replace NVRx's evidence/history/policy owner with a competing model policy.
8. Separate framework in-job restart, scheduler allocation requeue/replacement, and Ergora outer attempt/adoption. Pinned Bridge documentation scopes fault tolerance conservatively to Slurm/ft_launcher with accessible checkpoints and excludes NSys/Nsight Systems profiling; other profiler combinations need their own version-specific evidence; a non-Slurm Skill snippet is not a tested support matrix. NVRx deprecated in-process restart in v0.6 and removed it from upstream main after v0.7; old config fields do not guarantee a current module. Use matched supported versions, not an unconditional upgrade of the model stack. Do not enable both NVRx and legacy MCore straggler detectors. Straggler observation need not stop training; an explicit supported stop policy is separate.
9. Check durable checkpoint completion, not only enqueue, a marker, local save or load exit0. Identify format, async completion, all-rank shard/state coverage, storage/replication fault assumptions and actual commit; node-local storage cannot survive arbitrary node loss. Recovery verification compares the next optimizer update with uninterrupted execution, including RNG/dropout, sampler/data order, trainable adapters/modalities and relevant mesh state. Verify useful work, duplicates/lost steps, all-rank progress/exit, held-out quality and total recovery wall/resource cost under the original budget. Fault injection may affect only the owned accepted job. CPU/offline analysis, successful submission and real distributed recovery are different evidence levels. Hand each missing operation to its original executor/framework/evaluator; recommendation or native success never grants adoption authority.

Complete with a direction-specific coverage matrix, supported observations and contradictions, smallest next checks, unique owners/identities and explicit unverified operations. Cross-direction numerical, memory, graph, communication and measurement contracts remain in force; a recovery feature cannot borrow their acceptance.
