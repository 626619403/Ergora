# Memory-snapshot evidence and difference proposal

This Ergora-authored offline resource synthesizes the fixed capture/parser sources below. It reviews supplied trusted reports and proposes bounded diagnosis. It neither installs or executes a parser nor authorizes this readonly leaf to deserialize pickle, inspect arbitrary files, allocate a GPU or change capture settings.

1. Freeze original snapshot/report hashes and provenance, capture/parser/PyTorch/framework versions, selected device/rank/stage, model/config/data/checkpoint identities, workload/step/warmup and allocator/graph settings. Distinguish actual provided bytes from a reported path or operator claim. The cited loader uses pickle.load and requires a trusted source; the original authorized parser owner must establish that trust and bound RAM, file/event/rank counts, wall time and derived outputs. The Skill's 10-20x file-size RAM suggestion is an estimate, not a guaranteed bound. Prefer complete trusted text/JSON summaries for this leaf; a URL or filename does not expose the raw snapshot. Complete with a source/coverage contract or the smallest missing report.
2. Check the actual capture path rather than reusing an old example's baseline or line number. In the pinned Bridge setup, allocator history starts before model construction for selected ranks, keeps up to 100,000 events and captures Python context; profile_ranks=[] selects all ranks, with [0] the default. The configured end iteration writes a rank-suffixed dump and an OOM observer can write a separate oom_rank dump. These are source facts, not evidence that any supplied run used that path or OOM occurred. Memory history and PyTorch profiler flags are independent; the pinned validator forbids both PyTorch and Nsight profilers together but permits snapshot history without either. Step replay needs actual complete ProfilerStep boundaries, not just allocator/NCCL/optimizer annotations. Complete with observed capture settings/history and missing markers, never an invented step mapping.
3. Separate dump-time segments from retained device_traces history. Distinguish reserved, allocated, active including active_awaiting_free, and inactive reusable blocks; awaiting-free bytes are not yet reusable fragmentation. Report binary/decimal units explicitly. A PyTorch allocator snapshot does not include every direct CUDA/NCCL allocation or establish total physical-device/host/pinned usage. The cited helper selects the first active device and estimates a baseline from segments and recorded frees; verify selected-device scope and accounting before accepting an aggregate or a multi-device interpretation. Complete with supported totals, history coverage and independent device/host observations still required.
4. Check recording start, ring-buffer loss and unmatched frees before using reconstructed absolute peaks. Missing original allocations make the estimated baseline and attribution uncertain; no trace or missing stack is not zero memory. Source tables rank visible allocations and need not sum to absolute peak. Compare matching rank/stage, logical step, allocator and capture settings; the same elapsed second or numeric step label across different warmup regimes is not automatically comparable work. With no step markers the comparison's full-trace fallback does not recover per-step semantics. Graph pools retain memory despite fewer allocation events, so a quieter trace does not prove lower peak. Complete with qualified baseline/delta/peak and unmatched/missing shares rather than forced reconciliation.
5. Diagnose in a finite order: overview capture quality and device selection, compare compatible summaries/timelines, choose one aligned divergence window, then inspect live allocations and source frames there. Preserve frame-grouping/filters, graph/RNG/address-lifetime context, incomplete steps and uncertainty. The cited HTML plot loads Plotly from a CDN; writing a plot does not make it fully offline or authorize browser network. Source-only parser or formatting output is not independent correctness evidence. Complete with reproducible original and derived identities, candidate explanations and one smallest discriminating next observation; do not silently change parser, trust source, device, rank or workload.
6. Hand capacity/recompute/offload/graph interventions to their direction and the original trusted runner. Require independent numerical/gradient/optimizer/quality and checkpoint/RNG/data-order/next-update checks for actual changes; measure all-rank phase peaks and paired unprofiled end-to-end work separately from capture. A snapshot difference alone is not throughput, all-rank headroom, leak proof or adoption. Bound setup/capture/parser/cache/storage and recovery costs and preserve unavailable/incomplete/failed/no_gain/noise/unknown evidence. This leaf cannot collect another snapshot, stop part of a rank group, modify the trusted evaluator or approve a candidate.
