# Profile and trace diagnosis proposal

This Ergora-authored offline resource synthesizes the fixed sources below. It guides evidence review and the smallest discriminating next capture. Selecting it does not install Nsight, HTA or a collector, or authorize this readonly leaf to run SQL, export files, launch a workload or acquire GPU counters.

1. Inventory the original immutable reports and hashes, capture command/tool/schema versions, exact model/framework/container/config, dtype, batch and effective tokens, user step definition, graph state and rank/host/GPU/stage/group mapping. Record supplied data separately from operator specifications. Never infer rank or stage from a filename, treat an absent event as zero cost, or claim a source was inspected merely because its URL appears below. Complete with an explicit analysis scope, original identities and missing evidence.
2. Separate report collection, offline analysis and independent performance evaluation. An installed native CLI or MCP must have its actual operation/version and permitted input, scratch/cache, dependency-install and network effects checked by the original owner before use. R7 records that query-like operations can create cache or fetch dependencies; SQL inspection is not automatically side-effect-free. Inspect actual tables, column units, diagnostics and join cardinality before adapting a versioned recipe. Preserve originals and hash derived outputs. Nsight's proprietary tool license is distinct from this authored resource and Bridge's source license; no NVIDIA binary or third-party server is bundled here. Complete with approved available operations or a precise unavailable boundary, not an implicit tool fallback.
3. Establish steady iteration windows from the actual trainer/NVTX anchor, cross-checked against another stable signal; clip all device intervals to that ROI. Exclude warmup, capture, profiler start/stop and flush boundaries, record n and spread, and stop if anchors disagree materially. Compare same-run unprofiled trainer steps under identical work to measure perturbation; the PROFILER_OVERHEAD table is not total slowdown. Do not subtract it as an automatic correction. Complete with window/units/coverage and whether absolute budgets are perturbed, or a missing timing contract.
4. Survey every supplied rank before choosing the slowest trainer-step rank and representatives of each distinct PP stage or workload fingerprint. Rank0 is not automatically representative; different model parts are not interchangeable samples. Rebase timestamps with session-start metadata. Across hosts require independently justified alignment and residual uncertainty; a fitted collective-end offset is an estimate, not proof of perfect clocks. Distinguish earlier-start skew from late completion and keep uncaptured ranks unknown. Complete with explicit rank coverage, comparable windows and a bounded straggler statement.
5. Use clipped interval unions across streams, never summed kernel/stream durations as step time. Reconcile device busy+idle to iteration and compute busy+compute-absent to iteration. Split compute-absent into host-not-issued, resolved blocking producer and unresolved dependency delay, preserving residuals. Inventory exact configured NCCL and non-NCCL transport/dispatch/combine kernels; keep packing/routing/control separate from pure network transfer and report material unclassified/fused work. Exposed communication/copy is only a candidate upper bound until its dependency blocks the next compute. Complete with reproducible taxonomy, queries/filters, units, conservation checks and unresolved share, not a longest-kernel diagnosis.
6. Follow actual stream/event dependencies and verify join scope/cardinality; the cited event recipes use eventSyncId rather than reusable eventId. Zero event timestamps may require producer reconstruction. Graph replay can share launches or omit per-kernel launch rows. Report runtime-correlation coverage separately from source-callstack coverage; without exact source/callstacks retain trace observations and hypotheses, not source-level root causes. All-participant collective residence can provide a shortest-duration transfer proxy and rank waiting difference; it is not a direct bandwidth measurement. Complete with trace-verified/source-verified/inferred/unverified claims and evidence anchors.
7. Missing or denied GPU metrics does not invalidate all timing evidence or authorize permission changes. For sampled metrics report tool/unit/sample count and exclusive-residency share; missing samples mean unknown. Keep timing and counter passes separate and do not attach device-wide counters to a single kernel without evidence. Nsight Systems placement/duration alone cannot establish roofline or instruction/occupancy root causes. For a valid same-profiled-step T and nonoverlapping recoverable critical-path bound 0<=R<T, T/(T-R)-1 is a throughput ceiling, not a forecast. Do not transplant R to an unprofiled T or add overlapping opportunity bounds. MFU additionally requires a correct unchanged workload/FLOP/precision numerator.
8. Return capture quality, per-step/rank budgets and uncertainty, evidence-backed ranked hypotheses, finite next checks, total analysis/capture resource cost and the handoff to the relevant direction and original trusted runner. Independent loss/gradient/update/quality/recovery and warmed-up paired unprofiled end-to-end measurement remain required before adoption. Retain incomplete-capture, tool-unavailable, measurement-invalid, failure/no_gain/noise/unknown outcomes. Missing reports produce explicit evidence requests, not invented traces or automatic new capture. The runner retains allocation, full-group stop/recovery and evidence approval.
