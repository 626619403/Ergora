# Model verification evidence contract

This authored resource reviews supplied model-support claims and plans independent verification. It does not install or invoke a validator, load checkpoints, execute helper code, download datasets, allocate a GPU or approve adoption. Preserve the original evaluator, thresholds, holdout and source artifact identities.

1. Freeze model variant/config and all weight shards/revisions, exact candidate/bridge/framework/environment, tokenizer/processor and complete activated input/mask/position/modality cases, precision, requested mesh and intended deployment/training goal. Distinguish original bytes from declared paths or card statements. Registered model names and schema-valid configs/cards are not functional evidence. Report each claim with original command, inputs, outputs, identity and observed outcome, or a precise missing/unavailable/unsupported boundary.
2. Use the pinned twelve-item core inventory without deleting difficult items: CPU and GPU HF-to-Megatron; CPU and GPU Megatron-to-HF; manual forward correlation; deterministic Megatron inference; pretraining; SFT; SFT checkpoint export plus deterministic HF inference; long-context SFT; PEFT; checkpoint resume. Keep unverified, verified, unsupported and not_applicable distinct, with evidence or reason. A summary index must agree with its leaf records; a schema validator only checks structure/consistency and does not execute or authenticate the claimed results. Optional performance is a separate hardware/model-variant claim: omit ordinary pretrain_performance when no canonical public recipe exists, retain it unverified when a canonical recipe exists but has no accepted run. FSDP/HSDP/weak-scaling evidence and convergence contracts stay separate where applicable.
3. Check lossless tensor conversion independently of forward correlation. Inventory every expected/missing/extra key, shape, dtype, shard, scale and architecture-specific transform, tied storage and full values; require exact roundtrip for a claimed lossless conversion. An intentionally changed representation needs declared tolerances and its own quality experiment. Save a persistent checkpoint and load it in a new process, with the requested real TP/PP/EP groups and complete parameter coverage. A toy test, one successful export, rank0 output or HF deployment weights cannot prove full training-state support.
4. Compare identical processed tokens/media/masks/positions and semantically aligned logits. Padded vocabulary handling and complete intended inputs matter. The pinned card's single-step forward criterion is same next token and cosine at least0.99; max/mean absolute logit differences are also reported diagnostics, not that card's pass thresholds. This is correlation, not strict equivalence or training/quality proof. The pinned compare_hf_and_megatron/compare.py prints token mismatch and cosine failures but does not turn those comparison results into a nonzero process exit. Consume actual metrics/flags against frozen criteria, never upgrade exit0 or a checkmark/title to success. If only synthetic/partial text was supplied, qualify the result to that text rather than claiming the helper was run.
5. Deterministic generation needs frozen decoding/seed and meaningful cases. Text does not verify image/audio/video paths; the pinned video helper's Omni-specific constraints do not grant arbitrary VLM support. For differences locate the earliest divergence and distinguish mapping, math, precision, routing and input mismatch. A module swap is a diagnostic experiment, not permission to change the production evaluator or evidence that the original is correct. Required unsupported modes remain explicit; do not weaken the oracle to get a pass.
6. Validate finite training, resume and task quality separately. Match initialization, data order, seed, precision, loss and optimizer/LR schedule before MLM/Bridge correlation; ten mock steps or a short greedy sample do not establish downstream convergence. Resume requires the next optimizer update, checkpoint contents, RNG/dropout, sampler/data order and any trainable adapter/modality state, not just load completion. RL smoke updates, rollout/refit and optimizer/checkpoint resume need their external-framework evidence. Independent held-out task evaluation fixes model/data/task versions, chat templates, few-shot/decoding parameters, seeds, sample outputs/statistics, uncertainty and cache identities; selection data and final holdout cannot be conflated.
7. Performance requires an actual exact canonical or explicitly modified recipe, matching workload/effective tokens and quality, warmed-up paired unprofiled end-to-end measurement, repetitions/spread/synchronization, all-rank phase/device and relevant host/pinned/NVMe peaks, total setup/conversion/capture/training/evaluation cost and recovery behavior. A prediction, short function timing, source example or functional training metric is not a tuned performance claim. Freeze baseline and candidate; assess interactions together and preserve failure/no_gain/noise/unknown. The original trusted runner owns execution/stop/recovery and the original owner adopts only accepted exact evidence.
8. Return a per-claim coverage matrix with verified observations, contradictions, missing evidence and smallest discriminating next checks; do not manufacture a new result schema or training ledger. Public summaries exclude credentials, private cluster wiring and personal paths; original full evidence remains in its authorized storage. Backend choice and evidence transport do not expand this leaf's inherited permissions. Complete when the selected review/design role has explicitly scoped every required claim and handed execution to the existing owners.
