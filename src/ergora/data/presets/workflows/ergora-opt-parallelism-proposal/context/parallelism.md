# Parallel mesh and topology proposal

This Ergora-authored offline direction resource synthesizes the fixed sources below. It provides bounded proposals, not an installed parallelism solver, recipe runner or measured training result. Apply it to the supplied exact workload; retain missing stack, rank and hardware facts explicitly.

1. Freeze model/weight/tokenizer/data identities, dense and expert structure, local Q/KV heads, optimizer/precision, sequence and image-length distribution, effective global update and allowed changes. Request actual per-node devices, memory, links, rank placement and the baseline's initialized groups. Complete when supplied specifications, observed facts and missing prerequisites are separately listed. Active MoE parameters do not equal all resident weights.
2. For an ordinary shared-PP mesh without GTP, extra stages or custom layouts, check `W % (TP*PP*CP) == 0` and `W % (ETP*EP*PP) == 0`; dense `DP=W/(TP*PP*CP)` and expert `EDP=W/(ETP*EP*PP)`. The common divisibility lower bound is `PP*lcm(TP*CP, ETP*EP)`, not the product of all dimensions; `PP*max(...)` is sufficient for this divisibility only when the larger mesh is a multiple of the smaller. Resolve omitted ETP from the actual runtime, not an invented default. These conditions are necessary, not complete feasibility: check dense/expert pipeline-group equality, supported rank order, expert/layer/head splits, SP/TP, actual attention/sequence/batch rules and native validators. Custom layouts and GTP need their own native constraints. Complete with each finite candidate's mesh, derived DP/EDP, rank/stage map and any rejected condition.
3. Start from a matching library recipe and a small justified set of legal candidates. Model-size/sequence tables and canonical hardware recipes are screening seeds. Prefer matching high-bandwidth domains to frequent communication, but measure topology rather than treating an NVLink heuristic as a universal ban. Record pipeline bubbles, imbalance, per-rank state/activation peaks and exposed communication; keep effective batch membership, token budget, loss weighting and optimizer semantics comparable when changing accumulation or degrees. Complete when each candidate has one falsifiable bottleneck hypothesis and an exact baseline comparison.
4. Keep mechanisms distinct. FSDP changes state sharding, static CP partitions sequence, HCP chooses a hierarchical transport, and dynamic CP chooses groups at runtime for packed microbatches. Model-specific vision DP over CP is a separate split/encode/project/gather path. A config name or constructor success proves none of their numerical behavior. NeMo Auto Configurator is a legacy generation/short-training workflow; nnScaler and Aceso produce plans for their own compilers/trainers. Preserve each native plan and version when selected, rather than translating its success into a Bridge layout or a GPU gain. Complete by naming the exact supported native consumer, prediction versus measurement, and unsupported requests.
5. Return finite candidates, constraints and rejected options; independent output/loss/gradient/update gates; paired warmed-up end-to-end step/token measurements, all-rank memory and total setup/checkpoint/evaluation cost; stop and rollback requirements. Initialization and finite short-run loss are screening evidence only. For a changed layout request supported checkpoint reshaping plus optimizer/step/LR/RNG/data-order/processed-token recovery checks. Keep prediction, OOM, failure, no_gain, noise and unknown as original evidence. The original trusted runner and owner execute, observe, recover and adopt.
