# Hierarchical context-parallel proposal

This Ergora-authored offline direction resource synthesizes the fixed sources below. Select it for a justified hierarchical CP question; it does not make HCP a default or provide an installed multi-rank runner.

1. Freeze model/attention/KV-head partitioning, exact stack and input/mask/dropout semantics, current TP/CP/PP/DP, rank placement, sequence distribution and per-rank memory. Request measured link hierarchy and the baseline's exposed attention/communication cost. Compare simple p2p and a2a before proposing HCP. Pure a2a's effective local KV-head partitions and divisibility depend on TP and the actual attention implementation; use its validator. Complete with a sourced reason for the hierarchy, or an explicit finding that the workload/topology evidence is missing.
2. For the cited `a2a+p2p` path provide two positive hierarchy levels: inner a2a and outer p2p, whose product equals CP. Check the applicable `sequence_length % (2*CP) == 0`, actual head divisibility and native attention/dtype/mask constraints. The cited TE integration needs TE>=1.12.0, which is a necessary source-level threshold, not certification of an arbitrary newer stack. Dynamic CP's runtime group selection is a separate mechanism. Complete with the proposed exact groups/rank map and each version-matched constraint or rejection.
3. In the cited Bridge snapshot HCP uses the MPU initialization path, `dist.use_decentralized_pg=False`; the decentralized path leaves `hcp=None`. Inspect initialized hierarchical groups and their delivery to the actual TE attention call. A flat CP group, a saved config string or a single-GPU helper that clears hierarchy sizes is insufficient. Older missing-size behavior can produce local-only attention and deceptively high throughput; preserve actual missing/incorrect group evidence. Complete when the exact path is observed, or retain path activation as unverified.
4. Plan independent comparisons of outputs/loss, backward gradients and optimizer updates against an appropriate trusted CP1/simple-CP reference with matched samples, full causal/sample/loss masks and predefined precision tolerances. Include supported packed/unequal lengths and all-mask SFT ranks when relevant, without importing unsupported combinations. Group creation and one finite-loss step are smoke evidence only; the cited sources do not supply dedicated Bridge HCP end-to-end acceptance. Complete with the oracle, required cases and each actual result or missing artifact.
5. Request paired warmed-up end-to-end token/step measurements, critical-path and stream/communication evidence, all-rank memory and topology/placement; count setup/capture/checkpoint/recovery costs. Keep effective global batch/token/quality semantics comparable and scope any combination with packing, offload, graphs or FSDP to its actual versions. Return the finite candidate, reasons against simpler transports, independent gates, stop/rollback and checkpoint/RNG/data-order recovery requirements. Configuration feasibility and library exit0 do not authorize a speedup claim or adoption; the original trusted runner and owner execute, observe, stop and recover.
