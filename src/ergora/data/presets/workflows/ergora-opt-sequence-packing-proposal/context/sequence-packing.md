# Sequence packing proposal

This is an Ergora-authored offline decision guide. Apply each path's actual configuration and model/attention implementation; packing is a training and data-order intervention, not a universal token-utilization switch.

1. Freeze model/framework/data/tokenizer/processor identities, sample and length distribution, train/eval topology, TP/CP/SP/DP/PP, logical microbatch/global batch and resource limits. Specify causal/prefix/document boundaries, position IDs/RoPE, labels, padding, loss mask and loss numerator/denominator. Request actual baseline source and loss-bearing tokens, sample IDs, truncation/drop/duplicate counts, rank imbalance, host/device peaks and caller time. Complete when proposed workload capacity is separated from observed valid-token work.
2. Choose one native packing path and owner: offline dataset preprocessing; in-batch construction within one rank's logical microbatch; Energon's per-worker candidate buffer; or global-batch packing across DP. Their state, buffering, metadata and constraints differ. Use the real fixed-version `data/packing/config.py` and `in_batch.py` interfaces; older Skill import paths are not authoritative. Buffer size counts candidate samples per worker, so image/video and prefetch memory require separate host accounting.
3. Resolve alignment from the actual TP/CP/SP and evaluation topology. Distinguish constituent-sequence alignment from final pack width, logical microbatch size from physical THD rows, and physical padded offsets from actual sample boundaries. Inspect `cu_seqlens_q/kv`, padded offsets, max lengths, masks and the attention backend receiving them. EOS alone does not prove isolation. Fixed token width does not fix metadata count. Graph capture involving offline packed attention has its own fixed-width/padded-metadata validator path and needs actual execution proof.
4. Verify every path-specific restriction against the installed stack. At the cited Bridge snapshot, Energon/global-batch runtime THD requires MBS1, per-token loss, `average_in_collective=False` and excludes CUDA graphs and PP; global-batch also rejects VPP, Megatron FSDP and Mamba hybrid. Do not transfer that entire restriction list to ordinary in-batch packing. A boundary-aware MTP model path exists in the snapshot, so an older blanket MTP prohibition is insufficient; inspect actual model rolling, labels and padded metadata. Default cross-DP balancing and optional dynamic-CP scheduling/group requirements are separate choices, not general support promises.
5. Plan independent packed-versus-baseline forward/loss/gradient and optimizer-update comparisons with the intended sample boundaries and weights. Check cross-sample attention, MTP rolling, padding entering MoE auxiliary statistics, loss-bearing token denominators, DP reduction and gradient scaling. A mean of per-microbatch means can change gradients when valid-token counts differ. Shuffle, pack membership, truncation, drop-last, worker queues and checkpoint/resume order are explicit semantic changes; preserve or independently evaluate them rather than asserting quality from equal token slots.
6. Return one bounded native-path proposal, resolved metadata/config prerequisites and the smallest discriminating comparisons. Request warmup, preprocessing/first-batch cost, worker/rank memory, actual source/loss-bearing token throughput, paired complete-step timing and restored-next-step evidence. Configured capacity counters are not valid-token throughput. Keep numerical/quality gates, trial/resource limits, stop and rollback with the trusted runner and owner. Missing original data, masks, runtime support or measurements prevents an executable/benefit claim.
