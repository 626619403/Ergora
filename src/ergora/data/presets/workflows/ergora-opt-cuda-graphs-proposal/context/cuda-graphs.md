# CUDA Graphs proposal

This Ergora-authored offline synthesis applies to the supplied exact workload. Fixed source links identify researched behavior; the selected leaf cannot fetch them or run capture. Use the actual installed revisions before proposing executable controls.

1. Establish whether host submission gaps are on the caller's critical path. Freeze model/code/config, shapes/strides and their distribution, training or inference mode, mesh, compiler/attention backend, device/rank topology and resource budget. Request an eager or existing compiled/library baseline trace and paired caller timing. Complete when launch overhead is distinguished from compute, exposed communication, input stalls and synchronization; a kernel count alone is insufficient.
2. Choose one narrow capture scope. Distinguish a compiler graph from a CUDA launch graph, and successful capture from actual replay. `torch.compile(fullgraph=True)` and `dynamic=True` do not establish either. In the fixed Bridge implementation, the full-iteration wrapper and separately gated optimizer graph have distinct owners; record actual forward/backward/optimizer coverage and fallback. The helper supports old and new Core controls, including explicit module scopes: use the installed fields and validator, rather than copying an older Skill's scope table.
3. Specify replay invariants: input/output shape, layout and address lifetime; in-place updates of static inputs; output, workspace and graph-pool retention; stream/event joins; warmup and capture initialization. Account for host side effects and synchronization that replay cannot reproduce. Shape/path bucketing or CUDAGraph Trees can require additional recordings and retained pools. Compiler dynamic shapes do not remove capture cost. Native conditional/update APIs and specific PyTorch backend paths do not imply arbitrary Bridge Python control flow or training support.
4. Validate RNG/dropout progression and graph-safe generators/trackers, forward/backward and optimizer state, AMP/scaler/hooks, custom operators, recompute and checkpoint-restored next steps. Match Bridge/Core/TE/attention versions and model spec for PP, MoE, offload and packed attention. At the cited snapshot, offline fixed-width packing and padded `cu_seqlens` have a distinct validator path; runtime THD packing has different graph restrictions. A validator branch is eligibility evidence, not a completed GPU test. Preserve independent finite-loss/gradient gates when checks are moved outside capture.
5. Return a bounded baseline/single-scope comparison with exact proposed controls, all assumptions and unverified combinations. Request actual replay/engine evidence, cold setup and recording cost, per-rank graph/device peaks, paired steady caller timing and amortized total cost over the intended run. Set numerical/quality gates, resources, stop conditions and rollback to the original baseline. A legal capture, lower host overhead or microbenchmark gain does not prove end-to-end benefit; retain no-gain, noise and missing evidence. The trusted runner executes and the original owner decides adoption.
