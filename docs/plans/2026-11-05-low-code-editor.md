## 目标与保护

让用户通过列表、属性表单和连接编辑同一个工作单元草稿，并看清保存修订、错误和冻结任务的区别。继续使用已有版本化JSON、JSON Schema与`work_units[].depends_on`；布局/视口单独处理，不改变执行摘要。六阶段、可信集成/验证/审查和正式任务入口保持，试验仅覆盖两个开发模板；训练仍使用既有入口。

F6.1先做开发者可复现的限范围原型，用同一编辑旅程比较已随包Cytoscape及原生表单、React Flow及JSON Forms。选型依据是实际操作、构建与维护成本；研究结论不自动成为默认依赖或支持承诺。

## F6.2 与 F6.3 后续节点

F6.1选型后，F6.2按以下顺序形成可验收切片，每片均有新独立审查和精确交付：

1. 编辑状态与草稿所有权：图/表单/JSON共享一份语义输入，布局独立，保留现有项目/请求世代边界。
2. 有限编辑命令、撤销/重做与未保存状态：增加/删除/重命名单元、修改字段和依赖；没有任务执行副作用。
3. 显式校验/保存与修订冲突：失败保留输入，迟到回复和跨项目切换不能污染当前草稿；后端权威错误定位到对象/字段。
4. 完整浏览器旅程与包验收：两个开发模板往返、并发/失败/重开、键盘/窄屏，验证实际声明的操作，不镜像实现新增冗余断言。

F6.3再处理分组/搜索、键盘替代与只读运行叠层，以及50/200/500节点的限定容量测量。超出正式模板上限的数据只用于图交互测量，不宣称可编译/执行。后续F7–F10保持各自通信、会话、训练和持续改进边界。
