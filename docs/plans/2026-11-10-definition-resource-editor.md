## 固定交互与状态

1. **原包文件与完整读取。** 原文件表来自固定详情的 files，显示 SHA、执行位；标准 JSON 可下载，只经原正文入口编辑。明确点击“完整读取”或“下载原文件”后，沿 D2 的最大 65536 字节窗口连续读取。每页核固定基准/path、SHA、执行位、size、offset 和实际字节数，拒绝不连续或不前进的结果；失败或迟到不把片段变成可写草稿。完整重建后才解码为文本或下载。严格 UTF-8 解码保留 BOM（ignoreBOM:true），二进制只保留原字节／下载，不能用替换字符解码。小包旅程不代表最大包容量。
2. **文件草稿。** 一个明确路径的草稿含 op、执行位原文及完整文本或 base64 字节；路径/执行位暂时无效仍保留原文。新文本或上传都是完整 write，默认保留现存执行位、新文件默认无执行位；显式执行位限可移植位图，最终准入由库处理。上传读取前按 File.size 限定原 10MB，避免先分配不受限内容。文本编码须可无损 UTF-8 往返，不能静默替换未配对 surrogate。delete 只指定文件，mkdir 只指定目录。读取原文件前若有文件草稿，须先暂存或明确放弃，不能静默覆盖。
3. **未应用操作。** resourceBuffer 是相对固定原包的完整工作操作集合，null 仅表示没有未应用集合；首次编辑必须从已采用 resourceChanges 深拷贝（从未采用时才从空集合开始）。同一精确路径的明确暂存替换该项，追加/编辑/移除其余项均保留全部已采用操作。显式空操作对象表示操作者明确去掉全部操作，不能用真假值回退到已采用集合；放弃工作集合才恢复已采用值。读取/编码并保留新字节前，按精确路径替换后的完整集合核最多1500项、decoded写总字节最多10,000,000，先扣旧项再计新项；上传先用File.size，文本先核完整UTF-8字节（有界编码、不截断），超限保留原集合和已有草稿并提示CLI。采用、恢复与历史消费同一受限形状；不以quota错误代替分配前预算。大小写和祖先/后代冲突交 D2 拒绝，不在页面新增第二套算法。可逐项编辑/移除或明确放弃未应用操作。添加/修改资源声明仍用已有标准 JSON/YAML 的 resources 字段，合法占位摘要在预览后更新；新增 Skill 必须逐文件加入完整树，省略文件不会推断删除。表格和说明区分声明资源与普通附件。
4. **预览。** 已应用正文与工作 resourceBuffer（无该缓冲时用已采用操作，首次可为空操作对象）组成固定请求。未应用的字段/JSON/YAML、未暂存文件草稿阻塞预览；暂存操作允许预览。回执展示建议正文、文件 before/after、目录变化和完整 candidate，不能修改任何已应用值或工作字节。固定请求的完整操作、原基准和世代一并留在仅内存 preview；迟到结果只提示重试。
5. **采用。** “采用资源摘要”重新核当前会话及世代，使用原正文转换入口生成建议 JSON/YAML。如会改写自定义正文排版/注释，沿 C3b 明确同步确认；取消保留全部缓冲。异步转换期间有新编辑则不采用。成功时原子写入建议 definition、已采用 resourceChanges、acceptedCandidate，并清相应工作操作，进入同一已应用历史。原操作字节不能被响应内容替换。
6. **失效与发布。** 正文/字段/文件/操作变化立即清检查、preview 和当前 acceptedCandidate。有任何未应用缓冲时不能检查/发布旧快照。已有 resourceChanges 但没有对应接受身份时，须重新预览并采用；未用资源路径的旧正文修订保持原行为。check/publish 发送已应用正文、同一已采用操作与接受身份，库完整重建；成功回执、未知发布及相同显式重试沿 C3b。发布期间较新编辑保留，不能被回执降级。
7. **历史。** 一份已应用快照共同包含 definition、两格式已应用/规范文本、已采用 resourceChanges、acceptedCandidate 和所选实例；不含文件草稿或未应用操作。撤销/重做原子恢复这些值并清旧检查/preview，恢复的接受身份仍需重新 check。历史最多 50 份／4MiB，计入完整 base64/资源字段的实际序列化字节；单份超限只保留当前快照并提示。不得回归 C3b 的 S5 未应用正文进入 applied history 问题。
8. **恢复与下载。** 保持原编辑器 key，以 checkpoint version 2 保存两种已应用状态和全部未应用字节；只接受原 version 1 无资源字段的明确旧形状并迁入空资源状态，未知/部分新形状拒绝。先校验缓存资源/接受身份/草稿形状、完整 canonical base64 及原总量，再沿已有转换入口核已应用 JSON/YAML一致性；无效缓存保留原始下载、禁止继续发布。缓存不是准入事实，preview/check 不持久复用。已采用身份可恢复但必须重新 check。quota 失败明显提示，“下载定义编辑缓冲”包含所有已应用/未应用正文与操作字节，明确不含未编辑原包（另行 CLI export），不称独立完整包。
9. **目录与异步隔离。** File.arrayBuffer、分页读取、预览和采用均受原 home/key/基准/世代保护；换 home、换版本、清缓存或较新输入后不能写入当前其他会话。失败/晚回复不能替换已存工作缓冲。会话继续使用一个原 request 所有者，不引入并行上传状态机。完整 HTTP 请求沿原 4MB（含 base64）；明显超限时提示使用 CLI --resources，保留全部缓冲，不分片或自动重发。

状态以“已应用三项”和“未应用草稿/操作”清楚分离；具体局部函数留在已有会话所有者，不新增只有一次透传的模块。浏览器仅核传输/缓存事实，不重复完整产品准入。文本安全渲染与资源内容不执行的原约束保持。
