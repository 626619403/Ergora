# Q1.1：精确本地审查材料包

日期：2026-11-15。承接 [Q 总计划](2026-11-15-domain-review-optimization-quality.md)，逐步结果见 [交付](../delivery/2026-11-15-local-review-packets.md)。固定基线 `eecd90aa70c9268144af1161ade9076790dabf92`，分支 `refactor/architecture-foundations`，开始时工作树干净。

## 行为与边界

增加不依赖项目状态、模型或服务的 `ergora review prepare / verify / read`。用户提供本地 Git 仓库、声明的仓库身份、完整 base／head 提交 ID、原需求，以及显式选择的完整调用者／配置文件和可选检查原件。默认以唯一 merge-base 比较，也允许显式直接比较 base；三种身份分别保存。包包括全部变更文件在比较前后的完整内容、选取的上下文、适用的祖先 `AGENTS.md`、完整 diff 和原始材料摘要。上下文依赖发现仍由操作者负责，不宣称自动穷尽调用者。

只读本地 Git 对象；不 checkout、不执行仓库指令／hook／filter／外部 diff、不联网补对象。拒绝不完整对象、LFS 指针、二进制、符号链接和子模块等首版不支持的资料。重命名按删除＋新增表示。输入与输出有明确字节界限，超限拒绝发布而非截断；已知变更清单可用时在失败中列出本包未覆盖范围。

可移走源仓库后离线验证包摘要、源文件引用、Git blob ID 和内容摘要。可传独立渠道取得的整包 SHA256。离线自洽不证明来源真实性、Git 祖先关系、全仓库依赖完备性或检查可信性。原需求和检查均保留操作员来源，读取正文不授予执行权限。外部建议性审查不伪造正式任务、候选批准或平台 approve。

## 实现所有权

- 将 `reference_executor` 的有界二进制 Git 命令和批量完整 blob 读取提取至标准库模块 `git_materials`；实际消费者是原六阶段 executor 与新离线包 owner。保留原材料形状、权限回调和候选／批准／恢复流程。采用已有 Git 2.43 最低版本约束以禁止隐式 lazy fetch。
- `review_packets` 持有包的采集、内容完整性与发布；沿用 JSON Schema／重复键拒绝和 `asset_trees.publish_directory` 原子不覆盖目录。使用现有 Git CLI，不增加依赖、数据库、调度器、插件层或工作流格式。
- CLI 在创建 `State` 前分派；Schema 随原 wheel 数据打包。新测试加入已有 Linux 分组，不增加 CI job。
- 借鉴已有完整审查材料、只读候选检查和 handoff 的来源／完整性边界；Q0 一手研究确认完整源、需求和局部规范比仅 diff 更适合领域审查。本片不复制第三方未核许可实现。

## 验收步骤

1. 实现完整本地采集、离线读取／验证、严格大小与新目录发布；记录实际范围。
2. 用真实临时 Git 验证分叉分支、base／diff-base 区别、删除／改名／CRLF／Unicode、未提交工作区不混入、显式调用者和祖先规范；测试源仓库移走、篡改／悬空引用和失败不留成功包。
3. 核对禁 hook／外部 diff／隐式 fetch、环境 Git 变量隔离、不支持源和配置相关的容量界限。回归原六阶段完整材料及导入依赖边界，保持 283 份冻结参考不变。
4. 构建非 editable wheel，运行安装后 CLI 和受影响原调用路径；更新真实使用说明和架构依赖。
5. 使用 Ergora 原审查模板真实审阅这一片，再由新 fresh-context 独立审查者核原要求、固定基线、完整变更和实际证据。修复实证问题后普通提交／推送，核完整远端与自己的适用 CI。
