## Profile 在循环中的位置

`原任务与约束 → 源码依赖／数据流／生命周期及去冗余清单 → baseline／对应阶段 → profile 采集与诊断 → 有限候选选择 → 原开发／实验执行 → 数值与收益验收 → 下一轮诊断或停止`

已有 `training-optimization-v3` 先引用 `ergora-training-flow-map@1.0.0`，其 Skill 要求分别给算法图、执行依赖图与生命周期表；节点覆盖取数、forward、loss、梯度／collective、optimizer／scheduler、验证／保存与恢复。保留这一真实 owner，不另建同义分析角色。现有图是只读提案路径，独立叶仍需操作者明确提供完整前驱；新循环的消费和执行需另验。

Profile Agent 每轮参与诊断；重新采集由明确政策决定，不能把旧候选报告重标为当前候选。基线、新瓶颈、回归或证据不足时给出新的有界请求；复用旧报告须保留其版本和适用范围。无 profiler 的速度窗口与有采集开销的诊断窗口分账。

分析角色保持只读。实际采集由原可信 runner／job／process owner 持有；不因增加 Skill 就赋予 shell、设备、网络或审批权限。操作至少分开报告命令发现、实际 capture、实际 readback 和权限／版本限制。工具不可用或不支持的操作明确失败；只有既定政策允许的可选采集才可记录 unavailable 后继续。

工具选择不限于 nsys、torch.profiler 和 ncu。Agent 按实际瓶颈探索可用的主机、GPU、内存、通信、Python／编译诊断等工具，先做最小实证，再把适用条件、输入格式、操作、错误与证据沉淀为有版本的候选 Skill。确有稳定消费者时复用或扩展适合的 MCP／工具组件；CLI 已足够时不为每个工具另造 server。安装、认证、支持声明、采集与读回分别验收，旧角色／Skill／manifest 不原地升级。新的 Skill／MCP 不能隐式扩张父子权限或读取其他 owner 的运行。当前 ncu 权限拒绝不阻断其他方向，既不重复碰撞权限，也不提权绕过。

每轮材料至少绑定：原 baseline／candidate、实验与 run 身份、完整配置与阶段、环境／设备、请求与实际工具、采集命令和窗口、原始 artifact 身份、报告与热点依据、未核项和预算／停止事实。大报告保留原件并以原内容身份引用，不放宽现有 wire／reader 容量或截断后判成功。

报告复用原 `ergora-evidence-report-author@1.0.0` 的通用证据与 Markdown／静态 HTML 合同，以新版本挂载优化报告 Skill 与结构参考。不同阶段／硬件／有效工作量分表；可比结果层次递进、每项只列自身配置，组合增益不拆成虚构单项收益。操作者给定示例只用于结构抽象，原业务正文、方法、数值和图片留私有原件；runtime 参考自包含，不依赖内网文档访问。

## 保留的不变量

- 复用原 Temporal、实验、runner、比较器和证据 owner；不另建训练账本或通用调度器。
- 旧授权／输入／工作流历史保持原版本；新合同明确版本，不把最新配置补进在途任务。
- attempt-before-send、unknown 只对账、原 clock／cleanup reserve、唯一执行与 reaper、候选绑定及停止后的禁止启动均保持。
- 搜索和 Profile 调用消耗事先声明的预算，不隐式多调模型、不续预算、不因恢复重发。有限候选不能静默扩为无限探索。
- 不自动批准、合并、发布模型或晋升 baseline；测量通过与有权采用是两个结果。
- 不以降低精度、缩模型、跳过数据／校验或改变计量口径制造收益。不同阶段或有效工作量不得直接比较百分比。
