# F10a：项目记忆有效期与可见失效

日期：2026-11-14；基线`f47cd50fcce600fba92f64aff73982012f6e31c9`。[F10总计划](2026-11-14-evaluated-improvement.md)。本片复用`memory.py`、State迁移和原CLI／HTTP／长期记忆页面；正式Task选择冻结属于F10b。

## 持久合同与兼容

- 记忆修订新增可选`expires_at`，输入为带时区的ISO 8601时间，保存为UTC。不存在表示无限期；服务端观察时刻大于或等于到期时刻即expired。过期不改写原修订，也不删除正文、来源或已归档运行输入。
- 新建不传有效期仍无限期。更正**省略**有效期保留最新修订的有效期；明确传`null`才清除，新时间明确替换。CLI分别使用`--expires-at`和`--no-expiry`，HTTP区分字段缺失和null。这样旧调用不会无意延长新记录。恢复采用所选历史修订的有效期，包括已过期时间；不默认续期。
- 原`records`、CLI list、dashboard及search默认只返回当前有效记录。显式catalog返回同一判定时刻、原记录和valid／expired／deleted分类，供审阅；历史保持原字节语义，catalog不作为自动召回源。删除仍清空全部历史正文／来源且不可恢复，已归档输入和独立备份按原规则保留。
- 数据库升级为schema v5，沿原离线备份、原事务和全部21表的writer fence。迁移不改写旧记忆或增表；旧客户端重新打开拒绝新版本，升级前已打开的旧writer不能写新库。SQLite没有读触发器，无法撤销已经打开的旧reader或其缓存；升级须停止旧进程，再统一重启新版本。不宣称旧进程强制失效或降级可读。

## 检索与投影

本地检索在返回资料时统一判定当前有效性。ReMe仍是可重建投影：同步显式清理已删除／已到期镜像，不增定时器；远端请求后重新读取本地最新记录及时间，丢弃已失效、删除或修订变化的命中，忽略远端正文。清理可见性仍由原watcher决定，不能保证远端瞬时删除；本地过滤是返回内容的权威。

## 调用与结构

`memory`拥有时间校验、修订继承、catalog与过滤；CLI／HTTP只转交显式字段。dashboard保持既有有效列表，新增独立catalog读取入口，页面显式读取全部状态，并显示判定时刻／有效期，过期记录可更正／恢复，删除记录只读。页面复用原ui／api，异步读取限于本地view、逆序结果丢弃；不增后台轮询。表单使用带时区文本，避免浏览器本地时区转换或无意改变精度。

新辅助函数仅留在原owner：时间解析用于保存与有效性判定；catalog用于records／sync／search和显式读接口。没有新存储、调度、通用插件或日期库依赖。
