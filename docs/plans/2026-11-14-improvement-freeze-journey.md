## 范围与既有接口

在一个本地可信演示项目中，沿原 `handoff`、`retrospectives`、`skill_assets`／`evaluation`／`skills`、`memory`、`workflow_definitions` 和 `tasks` 完成一条组合旅程。复用原 native six-stage fixture 的登记、图、权限和预算，库与项目使用同一控制目录。合成来源明确保留失败与未知成本；合成评分只验证评价／采用合同，不证明模型或工程质量改善。

1. 保存同一完整来源包和三类基线，分别 prepare／check／export；记录精确输入、结果、候选摘要，核对准备和导出不移动活动版本。
2. Skill 候选使用同一预先固定的可信 suite 作 baseline／candidate 评价，明确采用；记忆候选明确保存为新 revision；工作流候选仅修订根描述，保留所有既有节点、引用、边、端口、权限和 limits，再明确导入及冻结新 manifest。
3. 正式任务 v7 明确选择新 memory revision、已采用 Skill digest／head revision 与新精确 manifest，从原 owner 派生新根资源。核冻结 envelope v11、全部祖先资料、逐叶完整输入与原权限／容量；归档记忆和 Skill 附件逐字一致。
4. 准备第二任务后，更正记忆、回退 Skill，使原选择失效；旧 preview 不得首次发布。原已创建任务及其全部冻结材料字节保持，原创建恢复读回保持原意图。明确恢复记忆并选择当前 head／revision，重新准备并创建另一个新任务；不能重用失效任务 ID 悄悄重编译。
5. 用实际 CLI、HTTP 和真实浏览器读取同一项目的候选、活动资料与已冻结任务。页面以原显式选择／读取路径为准；不重复前片全部宽度和迟到矩阵。保留实际运行原件、安装身份、进程收尾、自身原审查模板及新的 fresh-context 独立两轴结论。

先验既有公开接口。若均符合合同，只交付可复用操作手册与验收记录，不增加产品模块、测试套件、自动采用向导、调度器或第二账本。发现实证问题时先记录失败，再在所属 owner 最小修复并重验受影响范围。完整原 runtime 模型调用沿此前实际六阶段验收的原范围保留，本片若仅准备叶输入，不能宣称实际执行了这些叶。
