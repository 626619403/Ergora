## 可验收步骤

1. **盘点**：已有代码风格、深模块、诊断、测试与性能 Skill 及本地修订、包外链接／版本／许可风险；与现有角色逐项比较，给出独有增量。已完成研究与私有来源库存，不等于新增 Skill 已接入。
2. **原生资源包**：写两份短、可移植的 Ergora 标准 Skill：`ergora-codebase-quality`（仓库规范来源、实际依赖／测试接缝）和 `ergora-performance-diagnosis`（同一症状复现与按报告选工具）。通过原 metadata／tree/import 检查；参考文档在包内可达。只写有用增量；上游实质文本复制须保留对应精确许可。
3. **复用父模板继承**：优先将工程 Skill 放到新的重构根资源，让原执行／结构／正确性／测试价值子模板按现有继承合同获取；性能 Skill 放到新的只读分析根。原角色定义、子流程、23 个旧 preset 条目与旧版本保持。若父资源已能满足真实消费者，不另外复制四份 Agent 包。新版本／新条目由操作者明确选择，不热换已开始阶段。
4. **本地与公开入口**：在用户 home 下安装两份可发现 Skill，保存源摘要；演示原项目 `skill import` 与新 preset 的选择方式，说明独立调用 Skill 与冻结模板资源的区别。更新顶层 README／既有手册所需入口，不新建第二套手册。
5. **身份与行为验收**：noneditable 包／两 RECORD／283；23 旧条目、旧对象和权限／预算保持；新根的全部祖先和新增 Skill 参考进入实际只读会话。用合适的原测试保护导入／版本／权限风险，不为措辞匹配堆测试。实际角色案例核目标风格、真实调用链／恢复缺口、同症状复现和不匹配 trace 的诚实处理；不能用文字提案宣称 GPU 收益。
6. **审查与发布**：新自身原结构模板、新 fresh-context 需求／可维护性两轴；修复后复核。逐步更新本片交付与 PLAN，普通提交／推送现开发分支并验自己的 CI；不合入 main。
