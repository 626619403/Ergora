# F6.1：图形编辑器与表单的实测比较

日期：2026-11-05。前置为[LC1源码研究](2026-11-02-low-code-editors.md)，本次实现位于[可复现例子](../../examples/editor-comparison/README.md)，进度及审查见[交付记录](../delivery/2026-11-05-editor-comparison.md)。这次比较用于决定下一片的默认实现，不把库的宣传或研究 HEAD 当作验收。

## 实际结果

最终源码从锁文件 clean `npm ci --ignore-scripts` 安装36包、默认 `npm run build` 成功。固定 Node 24.18.0、React/React DOM 19.2.0、React Flow 12.12.1、JSON Forms 3.8.0、esbuild 0.28.2，Cytoscape 3.33.1 复用原资产。61个 lock 条目包含本机没有安装的其他平台可选包；不能把条目数说成实际下载包数。这个试验不增加默认 Python 产品的 Node 运行要求。

最终三个入口各在两个开发模板完成同一旅程：选择和修改属性、重命名与引用同步、添加/移除依赖、JSON往返、显式校验/保存、真实节点拖动与缩放，以及桌面/390px/表单键盘操作。共87次浏览器请求，其中66个POST仅指向草稿校验/保存；零pageerror，没有正式任务或Agent调用。每个方案/模板的成功草稿从原试验r1保存到r2。

环和 `../outside` 路径实际收到原服务端400，编辑输入/非法JSON文本保留；非法保存也被拒绝。摘要由原服务端计算，浏览器没有建立另一份规范化算法。移动/缩放只改变图库状态。390px检查覆盖页面无横向溢出和表单主操作可达，不代表任意缩放后所有节点都在视口内或完成全面无障碍审计。

另用20请求/2校验POST核两种图库的实际Shift点选/端口拖动连接、自引用重命名仍保留权威环错误、重名ID不修改输入及NoValidation表单空ID保护；零pageerror、没有草稿保存。因此最终浏览器总计107请求/68草稿类POST，六份成功草稿仍为r2。

JSON Forms 的默认模式没有通过：其 Ajv 动态编译在原 `script-src 'self'` 策略下报 EvalError，属性控件没有出现，首轮旅程exit1。随后使用官方 `NoValidation` 模式，仅让schema生成控件，仍由原后端显式校验；调整后的初轮和最终两模板旅程均通过，安全头保持。它没有客户端Schema错误提示，不是默认Ajv模式、任意schema或预编译接入的验收。

## 构建和交互成本

以下是三个**独立完整入口**的 HTML + JS + CSS + 同一schema文件之和；没有把共享bundle重复分摊给某个方案。gzip是本次每文件压缩后相加的字节数，当前试验HTTP实际发送原始字节，不能将它当成实际传输量。法律注释与完整许可文本是额外产物，不包含在页面自动请求集合中。这些数值也不是默认控制台的首屏大小。

|入口|JS字节|页面自动资产原始字节|逐文件gzip字节|esbuild输入记录|
|---|---:|---:|---:|---:|
|Cytoscape + 原生表单|442,043|447,564|144,198|6|
|React Flow + 原生表单|387,183|408,566|128,660|35|
|Cytoscape + JSON Forms|901,815|907,336|291,001|384|

表中为初审修复后的当前构建：Cytoscape重建时清除待连接起点，原生/JSON Forms入口随之变化，React Flow入口未变。初审前完整旅程和单次导航时间仍绑定原构建；修复后另验两个Cytoscape入口的跨模板/重命名取消及正常连线，18请求/2校验POST、零pageerror。例子安装说明也补上Web extra，并以新的独立venv实际安装、导入和启动验证。

这个构建中React Flow入口确实更小，不能凭“框架更重”反向推断它一定更大；esbuild输入记录也不是独立npm包数或复杂度评分。JSON Forms增加了渲染栈和校验相关运行代码，当前三个字段尚没有实测到足以抵消这些成本的产品收益。

固定headless Chromium155.0.8059.12、loopback、1440×1000、同一独立control且无并发模型工作下，最终导航到属性控件可用的单次观测为396/384/486ms。它包含项目dashboard与模板读取，使用同一会话和逐次更新的草稿库，没有冷缓存/弱设备/网络限速、多次统计或容量控制，因此不作速度排名或生产性能承诺。三组请求的实际时长和encoded/transfer字节与原构建记录分别归档。

两种图库都需要一段局部适配，将领域单元映射成节点/边，再把用户连接回写 `depends_on`。React Flow自带端口、控件和节点键盘移动；Cytoscape适配使用Shift点选连接，并保留公共依赖表单。它们都没有自动提供本项目的未保存保护、撤销/重做、修订一致性、迟到请求隔离或正式任务授权。这些仍属于Ergora编辑器状态与用例边界。

## 选型与限制

下一片保留已随包Cytoscape和原生ES modules，按固定的描述/字段映射改进原生表单，继续让现有后端拥有完整校验。两个方案已经满足此次编辑旅程；当前没有需要借框架迁移解决的测量瓶颈，也没有必要为了三个字段新增默认React/Node构建链。保留React Flow作为需要端口密集交互、成熟节点键盘行为或复杂自定义节点时的候选，再以对应真实需求重测。

不把JSON Forms引入默认发行。若以后确实出现大量动态表单、组合规则或多种renderer需求，需独立比较客户端错误收益、Ajv standalone与JSON Forms集成成本、CSP和多浏览器结果。官方[Ajv CSP说明](https://ajv.js.org/security.html#content-security-policy)、[standalone方案](https://ajv.js.org/standalone.html)与[JSON Forms验证模式](https://jsonforms.io/docs/validation/)支持这些技术路径，但本片只验证了固定工作单元schema的NoValidation渲染，不宣称已实现其他路径。

正式决定及重评条件见[ADR 0003](../architecture/decisions/0003-workflow-editor-stack.md)。F6.2继续补编辑状态、有限命令与撤销/重做、保存修订/冲突和错误定位；F6.3处理容量、分组/搜索和运行叠层。治理实际模板上限4、大型开发上限24，不能把后者说成两个模板都支持24。此次没有50/200/500测试、原型Windows/其他浏览器实测或任意拓扑执行验收。例子不是生产编辑器，打开页面仍从模板开始。
