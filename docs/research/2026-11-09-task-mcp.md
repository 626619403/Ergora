# AC3b.3：最小只读任务 MCP 的实施依据

日期：2026-11-09。范围：为[AC 计划](../plans/2026-11-08-agent-composition.md)的下一片提供可实施决策；这是研究，不是已交付的 MCP 能力。调查开始时 HEAD 为 `eee09efcba093839dba5407c474a7a5b46a3a2a0`，工作树已有未提交的 AC3b.2b 实现。依据 [ADR0004](../architecture/decisions/0004-agent-composition.md)、[ADR0005](../architecture/decisions/0005-composable-workflows.md)和[受限调用记录](../delivery/2026-11-09-composition-invocations.md)。本次仅读源码、官方资料、包元数据和本机 help，并执行依赖解析 dry-run；未安装 SDK、运行 MCP 服务、调用模型或修改生产代码。

## 建议决策

采用官方 Python SDK **`mcp==2.3.0`**，用它的 `MCPServer` 高层接口实现每调用专用的 stdio 服务。仅注册 `read`、`list` 两个工具，范围由可信代码从已核输入的选定叶子解析；祖先及自身声明的资源全部可达，兄弟、完整资产库和任意宿主路径不可达。可选项目读取只开放有效 `read` 已包含的 `workspace/...` 路径。写、shell、工具网络及外部服务仍不支持。

保留完整祖先 instructions/context/Skill 指令的现有内联交付，MCP 补足目录和附件的按需读取，不能用检索代替强装载。优先交付显式的独立调用模式；**不修改现有 AgentDefinitionV1、WorkflowDefinitionV1 或 CompositionInputV1 来塞入 MCP 字段**。以后模板声明 MCP 需要新的定义版本、schema、准入和实际消费者；本片不能宣称已完成模板 MCP 继承或正式批准链。

## SDK 版本、接口与依赖

2026-11-09 实查 PyPI：官方 `mcp` 当前稳定版为 **2.3.0**，2026-10-02 上传，wheel/sdist 均未 yanked，元数据标为 Production/Stable、Python `>=3.10`。Git tag `v2.3.0` 实际指向 `2118f14f8a19bc158d8a1cf90af58d85d187f849`。wheel SHA256 为 `dd0c44c089d16453e8ae31a3877a0054d7a2314caaa81f5e0541b9b1734b2377`；sdist 为 `8b147a50441cf059dc88c684e0aeed3687f0aa0f39c6cde7b90330effd2b34d8`。[S1][S2]

**不能沿用 `from mcp.server.fastmcp import FastMCP`。** 2.3.0 wheel 中该模块主动抛 `ModuleNotFoundError` 并指向迁移说明；v2 将高层类更名为 `MCPServer`。可用 `from mcp.server import MCPServer`，保留 `@mcp.tool()` 及 `mcp.run(transport="stdio")`；后者是同步入口，内部进入 AnyIO 和官方 stdio transport。类型注解生成工具输入 schema；工具异常会形成 `CallToolResult(is_error=True)`，领域准入及路径检查仍由 Ergora 写。需要低层客户端预检时也使用官方 SDK，避免手写 initialize、JSON-RPC、分帧及生命周期。[S2][S3][S4]

最小接口形状如下，只展示 SDK API，不是当前可运行的 Ergora 示例：

```python
from mcp.server import MCPServer

server = MCPServer("ergora-task", version="1")

@server.tool()
def read(path: str, offset: int = 0, max_bytes: int = 65536) -> dict:
    return scoped_reader.read(path, offset, max_bytes)

@server.tool()
def list(path: str = "") -> dict:
    return scoped_reader.list(path)

server.run(transport="stdio")
```

`scoped_reader` 是拟议的可信范围消费者。首片只登记工具，不登记绕过工具检查的原生 MCP resource/prompt、采样、动态工具或代理调用。`readOnlyHint` 等注解可以描述工具，但不能承担授权。[S3]

独立发行 **`fastmcp` 不是所选依赖**：PyPI 当前为 4.1.6，仓库为 `PrefectHQ/fastmcp`，并依赖其 `fastmcp-slim` 系列。不要把它的 `from fastmcp import FastMCP`、插件或客户端示例当作官方 `mcp 2.3.0` 的接口。[S5]

建议增加一个可选的任务 MCP extra，精确固定 `mcp==2.3.0`；无须 `mcp[cli]`、独立 `fastmcp`、MCP Inspector 或远端网关。SDK 的 CLI extra 只增 `typer`、`python-dotenv`；生产通过本项目已安装的 Python 模块启动服务，缺 SDK 时在模型前明确失败。虽然这里只用 stdio，发行元数据仍要求 HTTP/认证相关依赖，不能自行删减官方依赖。[S1][S2]

## 两个原生客户端的实际接口和证据层级

本机只执行了 `--version`、`exec --help`、`mcp add --help` 及 Claude 顶层 help，没有请求模型。版本分别为 **codex-cli 0.166.0**、**Claude Code 2.1.312**。已安装入口文件 SHA256 分别为 `e14fc83739c13c1074b12bd1acce4010c893c7f6fbfc1593b4a31d74cabb57af`、`4f4178ce41d83e23341ebfbaecdbcf8ea6bf7baea0690025abe49eeec3a5d01d`；前者是安装入口身份，不冒称底层二进制身份。

|事项|Codex 0.166.0|Claude Code 2.1.312|
|---|---|---|
|显式服务|官方 `[mcp_servers.<id>]`：`command`、`args`、`cwd`。通过每次调用的受控 `-c` 构造，不执行持久化 `mcp add`。[S7][S8]|help 有 `--mcp-config` JSON 文件/字符串，`--strict-mcp-config` 仅选显式服务。使用 `{"mcpServers":{"ergora_task":{"type":"stdio","command":...,"args":[...]}}}`；不写用户配置。[S9][S10]|
|工具选择|`enabled_tools=["read","list"]`；`disabled_tools` 在 allowlist 后应用。`required=true` 可要求启用服务初始化失败导致启动失败。字段既见官方文档，也存在此版本固定源码 schema；本次未运行验其强制行为。[S7][S8]|`--allowedTools mcp__ergora_task__read mcp__ergora_task__list` 表示免提示允许，**不是仅这些工具可见**。`--tools ""` 关闭内置工具；未选 MCP 工具可用逐个精确 `--disallowedTools` 剔除，服务端本身只注册选中工具。不能 `deny mcp__*` 后再 allow 两个工具来期待例外。[S10][S11]|
|ambient 配置|help 有 `--ignore-user-config`、`--ignore-rules`、`--strict-config`。strict 检查未知配置字段，不代表只允许显式 MCP，也不是隔离。沿现有空 cwd、关闭规则/Skill/hooks/apps/plugins/multi_agent/shell/web/项目文档策略，并单独注入服务。[S8]|help 的 `--restricted` 会忽略 user/project/local 设置，但 managed 设置及 `--settings` 仍可能生效；`--setting-sources ""` 亦不等于停掉全部扩展。`--strict-mcp-config` 只管 MCP 来源。|
|安全模式衔接|维持现有专用配置中仅推理字段来自操作者配置，MCP配置由可信代码生成。不能重新读 ambient config 来获得 server。|**不要假设现有 `--safe-mode` 加上显式 MCP 就可用。** help/文档称 safe mode 禁用 MCP 等定制，本次未验显式例外。help 的 `--bare` 明确允许显式 `--mcp-config`，但不读 OAuth/keychain，Anthropic 认证限 API key 或显式 apiKeyHelper；不能静默改变认证。应先验 `--bare --restricted --setting-sources "" --tools "" --strict-mcp-config`，或另验保留原认证的等效受控组合。[S10]|
|stdio 环境|`env` 是显式值；`env_vars` 转发具名环境变量，当前 schema还支持 local/remote来源；HTTP的 `bearer_token_env_var` 与 stdio分开。help 的 `mcp add --env KEY=VALUE` 存值，不是凭据引用接口。[S7][S8]|stdio条目有 `env`；官方记录 `${VAR}`、`${VAR:-default}` 可在 command/args/env/url/headers 中展开，缺变量可能保留原文而继续。此展开语义官方页面明确针对 `.mcp.json`，本次未验 `--mcp-config` 的等价性，不能据此声称安全注入已通过。[S9]|

Codex 对照源码固定到 tag `rust-v0.166.0` 的 peeled commit **`6ff1e1ca3b30fc8b914720681fcf5fe62e95f856`**，而不是用最新文档替代安装版本。上表中的 `RawMcpServerConfig` 含 command/args/cwd/env/env_vars、工具 allow/deny、required、超时等字段；CLI help本身没有列出全部配置键。[S8]

本片内置任务 server **不需要任何服务凭据**。不要将推理凭据复制到它的配置、argv、manifest、日志或回执；`env={}` 不足以证明子进程零继承。本次未核两端所有默认继承变量；建议受信启动器只向实际 server保留必要系统变量，移除凭据和 Python 路径注入，并用已安装包/固定解释器启动。后续外部 MCP 凭据使用逻辑引用，必须在调用前核存在且非空；注册、健康、认证成功与本次授权仍分别记录。不要依赖 Claude 缺 `${VAR}` 仅警告的默认行为。[S7][S9]

**缺服务必须由 Ergora 判失败。** Codex可用 `required=true`，仍需本机实测。Claude官方明确：`-p` 下 stdio首次连接失败会继续且不带该服务工具；它的 exit 0/合格最终 JSON 不能证明必要 MCP 存在。建议模型前使用官方 SDK在同一scope/启动参数下检查 initialize、工具清单和只读探针；再核本次原生运行的服务连接/工具回执，不能把预检进程当成原生CLI已经连上的证据。若现有 JSON输出不足，局部消费 `stream-json` 的 init/server错误字段或服务端每运行私有审计回执；缺必要服务、工具缺失或错误回执时即使模型回答成功也登记失败。[S9]

现有交付记录已证明两个原生 CLI 的 **text-only** 合成协议只提供 request_user_input / StructuredOutput、未执行伪造 exec_command/Bash，并排除了父目录规则标记。这是前片证据，**没有证明非空 MCP配置、原生allow/deny、safe-mode例外、凭据环境或服务强制失败**。本次研究不升级其验收结论。

## 最小所有者、API和版本模式

当前源码中 [`workflow_definitions._materials`](../../src/ergora/workflow_definitions.py) 仅合并结构祖先，保留 `sources` 和 `definitions/{kind}/{id}/{version}/{resource.path}` 逻辑 URI；`inspect_input` 核完整资产图，[`agent_runs.run_input`](../../src/ergora/agent_runs.py) 复制完整输入后交给 `agents.invoke`。现有资源schema只有 instructions/context/skill。完整输入含兄弟定义是完整性要求，不能因“已核完整”就把 `assets` 全部映射给叶子。原生参数的当前消费者在 [`agent_backends`](../../src/ergora/agent_backends.py)。

建议在现有所有者下增加一个窄模块，不另起网关或调度器：

|所有者|新增职责|
|---|---|
|`workflow_definitions`|继续核静态完整输入及祖先资源来源；从现有选定叶子结果提供投影依据，不拥有原生命令。|
|`agent_runs`|显式 `task-mcp` 调用模式、当前准入、项目/祖先/叶子 read上限、独立scope与精确副本、结果及服务失败状态；保留当前 `text-only` 默认和已有持久表。|
|拟议 `task_mcp`|冻结scope、受限路径读取、stdio服务、初始化/工具清单预检及私有服务回执；使用官方SDK，不加载外部任意server命令。|
|`agent_backends`|在既有ABC内声明/拒绝模式，拥有 Codex/Claude专用配置、allow/deny、版本支持及原生回执解析。顶层不按厂商重复分派。|
|`agents` / `processes`|继续拥有调用、超时、取消和进程树；stdio server属于这次调用的子进程基础设施，不能遗留独立后台服务。|

可以新增独立种类的 `task-mcp-scope` **schema_version 1**：仅含 `run_id`、输入digest、选定instance、投影文件及摘要/来源、workspace获准范围、工具名 `read/list`、读取/输出上限、策略摘要。不接受模板提供command、任意env、凭据值或活动版本指针。它是本次操作生成且真正被server消费的执行合同，不是修改旧v1定义；其SHA纳入本次调用记录，`formal_execution_authorized`继续为 false，不能宣称已进AC3c正式批准身份。原生配置和scope均由同一解析结果生成，防止只存一个未被消费的sidecar。

投影以虚拟URI查表，物理路径不向模型充当权限接口。普通 instructions/context只开放声明的文件，Skill开放其完整固定目录；不能为了方便开放文件的父目录或整个定义包。相同内容可去重但保存全部祖先来源。可选workspace投影不从项目cwd或MCP `roots/list` 自动扩权；Claude roots反映启动/附加目录，不等于本项目冻结的grant。[S9]

`list` 默认只列获准节点，递归也必须有条目/字节上限；`read` 按字节偏移和有界长度返回 `sha256/size/encoding/next_offset`。文本与二进制有明确编码，不能执行脚本、跟随URL或隐式读取环境变量；超限有明确续读/错误，禁止静默截去必需内联材料。不要把前缀不同的相邻路径误判为子路径。资源视图不暴露scope、协议文件、完整composition、库index和兄弟信息。

每次实际读取必须重新检查授权及文件类型。拒绝绝对路径、`..`、反斜杠/盘符/UNC、NUL、符号链接/junction/reparse point、特殊文件和链接逃逸；若要拒绝硬链接别名则显式检查link count。仅 `resolve().is_relative_to()` 加后续 `open()` 不能抵御替换竞态；Linux用逐级目录描述符加不跟随链接的打开，或先复制并完整核验私有快照。Windows没有等价实现时，应明确拒绝需要该保证的模式，不以lexical检查冒充强制。不可变资源仍核内容身份；项目实时文件需声明为本次实际读取内容并记录摘要，不能冒称创建输入时已冻结。

## 能力请求、上限与保证

现有grant与结构祖先/叶子的权限是请求及上限，MCP配置存在不自动增加权限。准入沿完整链验证；要求越上限或无法强制的能力明确拒绝，不能取交集后静默把必需能力丢掉。首片的可执行合同应明确如下：

|能力|本片应提供的语义|
|---|---|
|祖先及自身资源|全部必需指令保持完整内联；固定目录只读投影，由可信server处理路径、内容身份及范围。兄弟资源不可见。|
|项目文件|可选；仅有效 read范围。若实现不能满足链接/竞态边界则拒绝该子能力，不能自动开放native Read/Grep/Glob。|
|MCP工具|只有已核服务及 `read/list`；服务端不注册其他工具，客户端显式选择/拒绝；真正强制结论绑定两端实际协议验收。|
|写/模型shell/工具网络|请求在模型前拒绝；无对应server工具和native旁路。推理HTTP、stdio启动、日志及本项目状态持久化是可信基础设施，不能把它们记成“零子进程/零网络/零宿主写入”。|
|宿主隔离|**不提供。** CLI、server及操作者仍以可信用户身份运行；模型目录和工具选择、fresh进程、文件handler检查不等于OS/网络沙箱或恶意同UID用户隔离。|

只有已实测的工具及路径消费者可标 `enforced`；未测客户端组合先标待验证，纯提示约束为 `advisory`，未实现写/shell/network和外部MCP为 `unsupported`。不以定义里的sandbox字符串或只读工具注解替代证据。

## 六项高价值验收

1. **两后端真实装载和成功读取。** 使用各自已安装原生CLI、合成推理服务及官方SDK任务server，模型确实调用祖先/自身的 `list/read` 并收到独有哨兵；记录initialize、实际模型工具清单、调用/结果、scope与输入SHA、CLI版本及退出结果。只检测文本回答含哨兵不够。
2. **工具允许/拒绝。** 测试server额外提供一个无副作用的未选probe工具，两端实际请求只允许选中工具；伪造未选调用不得到达handler。服务端生产模式也只注册read/list。拒绝不得静默换成其他工具或后端。
3. **没有native/ambient旁路。** 同时布置父目录规则、Skill、插件及ambient MCP标记；它们不得进入请求或工具表。伪造 native文件、shell/web/子Agent工具时不执行哨兵副作用。明确记录仍保留的响应/交互工具，不把这种验证写成OS隔离。
4. **祖先完整、兄弟隔离和read上限。** root→parent→leaf每层Skill附件可读，所有必需内联正文仍完整；兄弟、完整assets/index、未声明同目录文件、未获准workspace路径既不可list也不可read。子权限收窄致必需祖先不可读时在模型前拒绝。
5. **路径/链接逃逸拒绝。** 对read/list覆盖 `../`、绝对/盘符/UNC、前缀碰撞、资源或workspace symlink/junction、特殊文件及读取期间替换。应拒绝并且不泄露目录项/目标字节；按实际支持平台验，不用Linux结果代表Windows。
6. **必需服务显失败及生命周期。** 缺SDK、坏command、握手/工具清单错误、启动超时、途中退出和取消必须有可读失败、原始回执及子进程结束证据；Claude即使最终JSON成功也不能通过。前置预检成功后再让原生启动失败，证明不会把预检当作正式连接；不暗中转回text-only。

本片未验：SDK实际安装/导入、客户端与2.3.0协议协商、任何非空MCP调用、上述两种Claude定制隔离组合、stdio默认完整环境、外部凭据/认证/健康、Windows链接和取消。GitHub REST版本查询此次遇限流，已用 `git ls-remote` 和固定tag源码补足身份；Claude Markdown直连403，实际打开了官方HTML页面。依赖dry-run只证明可解，以上六项均是后续验收要求。
