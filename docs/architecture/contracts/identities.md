# Content identities and digest contracts

English · [Documentation](../../README.md)

## Identity algorithms

|Identity|Current implementation and encoding|Why another algorithm cannot replace it|
|---|---|---|
|Evaluation manifest|`improvement.evaluation.manifest_sha256`: `json.dumps(sort_keys=True, ensure_ascii=False, allow_nan=False)` then UTF-8 / SHA-256, retaining default spaces|Original `_sha` only gains a semantic name; old evaluation-suite digests and candidate evidence must remain|
|reference canonical JSON|Frozen `dev_platform.contracts.canonical_sha` / adapter sha: sorted, UTF-8, unescaped Unicode, compact separators, reject NaN|Original compilation, requests, profiles, approvals and receipts use this identity, without merging evaluation digests|
|Skill directories|`storage.assets.digest_tree`: sorted relative paths; per-file content SHA and executable bits; file inventory retains original sorted JSON encoding then SHA-256|Script executable bits and content jointly form assets; hashing only SKILL.md or normalizing different newlines/bytes is insufficient|
|Static Agent packages|Shared `storage.assets.digest_tree` uses original Skill-directory algorithm, including agent.json and all ordinary attachments; file resources separately check original-byte SHA256, Skills complete directory digests|Exact ID/version points to a fixed package digest; JSON reencoding does not merge different packages, and resource readability is not permission/runtime evidence|
|Static Workflow packages/previews|Packages use original Skill-tree algorithm; previews use sorted UTF8, unescaped Unicode, compact JSON/SHA256, excluding their own preview_sha256|Includes exact root/all references, structural paths, graph/ports, complete static materials, source/assembly digests, permissions, explicit grants and limits; excludes future port values and is not a formal runtime manifest|
|Agent results / prompts / file artifacts|Original owners compute SHA over actual fixed bytes; results retain sorted JSON preserving Unicode|Actual content identities for different purposes, without unified “automatic normalization”|
|Offline backup manifests|`operations.backups.verify` computes SHA-256 of manifest.json original UTF-8 bytes; each file inventory records actual bytes, size and mode|Manifest identity binds this particular snapshot without rewriting referenced old Skill/evaluation/formal-evidence digests|
|Project registrations, projections and import previews|Sorted UTF8, unescaped Unicode, compact separators, reject NaN, JSON/SHA256; registration digest binds id/repo/normalized definition, preview additionally binds control_home/revision/bindings/differences/source SHA and projection digests|Only project top level owns bindings; old-file SHAs separately use original bytes, so whitespace changes invalidate import previews too. Old files are not reencoded to manufacture consistency|
|Issue responses|SHA256 of complete original response bytes from one successful GET; ETag and original updated_at retained separately, without response reencoding to calculate the same digest|Response whitespace/field-order changes also change SHA; observation time and configuration identity are separate. Content digests cannot imply task authorization, event deduplication or atomic-write versions|
|Candidate-comment identities|Reuse `development.envelopes.identity` sorted UTF8, unescaped Unicode, compact JSON/SHA256; opaque names in fixed body additionally receive JSON-literal and Markdown/mention-character escaping|intent/logical scope/attempt/observation each have different digests; native POST/GET responses separately retain original-byte digests. Markers, current matches or reencoded projections cannot prove original-request causality|
|Candidate-label identities|New kind `candidate-label-add` uses original schema v1 and schema v3 domain tables; freezes complete ID request, single label and service-returned issue/repo/label node IDs, without rewriting original C1 format|Only one label semantic slot per candidate; renaming/new request IDs cannot bypass it. ack saves only with original 200 lacking GraphQL errors, echoed values and target matching within original response's bounded page. clientMutationId is not an idempotency key; current query pages do not replace original receipts; GitLab labels are unsupported|

|Remote candidate observations|Original source/creation/run/export identity comes from tasks shared projection; original export owner reads current local ref and original base/candidate commits, while each platform complete-200 response digest remains separate|No persistent saving or reencoding of old intent; three ref comparisons stay separate, and 404 is indeterminate. Current repo native ID is not identity at original creation, nor a shared snapshot/CAS, and proves no original attempt, historical uniqueness or push author|
|Existing review links|`candidate-review-context-v1.json` owns saved documents and their review_request subcontract; State v4 adds only candidate_review_links, scope and document have separate canonical SHAs|Binds original source/creation/run/candidate/export; current native number/iid, global ID and node ID are saved separately. Unique per candidate; immutable retries return history. Complete-body null/empty values remain, with identical save/offline load/backup validation. Local context only, not remote attempt, snapshot/CAS or approval|

A2 fixed vectors, both compiled/request/profile identities, Skill executable bits and synthetic old states remain regression evidence. R2 only moves private `_sha` calls in tests to actual semantic names, without changing any identity fixtures.
