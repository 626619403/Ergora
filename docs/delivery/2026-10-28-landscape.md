## 用户要求

在 README 整理后，调研现有多 agent 协作工具的实现与定位；判断关系表示应采用新格式还是已有格式；分析 Ergora 的相对定位与优势；评估各层真实工具可配置、可替换的实现路径。

## 范围与基准

- 基于已完成的 README 与 v2.2 参考分发，保持当前执行源码、服务及六阶段协议不变。
- 以官方文档、官方源码仓库和协议规范为主要来源，记录访问日期和可核对链接。
- 按通用 agent SDK、状态/工作流框架、编码协作平台、可视化应用平台、通信与描述规范分别比较，避免把不同层级混为竞品。
- 覆盖主流及与 Ergora 最接近的代表实现，明确长尾与未实测范围；不宣称穷尽所有项目，不以文档缺少某项说明断言其绝对不支持。
- 本切片交付调研与设计建议，不实现新 DSL、插件系统、GUI 或后端适配器，不提交或推送。

## 计划与验收

1. 核对框架的 agent、任务、关系、状态、恢复、人工审批与扩展接口。
2. 核对 Agent Spec、OASF、A2A、MCP、Agent Client Protocol、AG-UI、JSON Schema、YAML/JSON 与通用工作流规范的职责。
3. 对照已有 `task / package / policy / binding` 编译边界，提出最小关系模型、工具绑定和兼容性验证方案；示例必须明确为设计草案，不能冒充当前可执行配置。
4. 输出带逐项来源的比较表、竞争定位、分层可替换矩阵、图形界面顺序和分阶段验收建议。
5. 静态核对文档链接、示例与现有实现界限；用新的独立 reviewer 审查后记录结果。
