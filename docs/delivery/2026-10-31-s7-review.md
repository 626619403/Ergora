### S7-1 · Medium：默认与可选 CLI 缺少空环境安装入口

位置：[docs/USAGE.md](../USAGE.md)（第29行）、[docs/AGENT_BACKENDS.md](../AGENT_BACKENDS.md)（第13行）、[scripts/install-agent.sh](../../scripts/install-agent.sh)（第8行）。

可达场景：用户按空环境步骤仅安装 Git/Python 和 Ergora，随后按首个项目步骤选择默认 Codex（或切换 Claude Code）并执行 `agent run`。`install.sh` 只安装 Python 应用与所选 SDK，`install-agent.sh` 只有 mini/Forge 两项；新手册既无 Codex/Claude 的安装命令，也无它们的官方安装页面。`agents.available()` 仅检测 PATH，实际调用直接执行 `codex` / `claude`，因此在刚完成所示安装的环境仍是缺程序，用户需离开交付文档自行搜索。

最小修正：在 Agent 手册增加这两种真实 CLI 的官方安装入口、基础版本/平台要求、PATH/版本自检和认证指针，从使用手册链接；明确独立 CLI 与冻结参考发行所安装的 Codex 配置的关系。无需自动安装或代用户登录。

### S7-2 · Medium：软链接安装根的幂等升级失败

位置：[scripts/install.sh](../../scripts/install.sh)（第34行）。

可达场景：`ERGORA_INSTALL_ROOT` 指向现有目录软链接；首次安装成功，原样第二次运行安装器（升级）退出 1，误报现有 `ergora` 属于另一安装。代码用逻辑 `pwd` 生成 target，再将入口的 `readlink -f` 物理结果与该逻辑路径比较。同一目录的两个路径必然不相等；`HOME` 自身包含目录软链接时也有相同路径风险。

最小修正：规范化安装根为物理路径，例如 `pwd -P`，或比较双方规范路径；继续保护实际属于其他安装的入口。

验证：在忽略的 `build/s7-review/install-symlink-probe/` 中执行真实安装脚本；仅以本地 stub 代替 Python venv/pip 和最终 CLI，全部写入审查目录。两次退出分别 0、1；第二次在 pip 调用之前失败。该复现证明路径/入口判断，不作为真实 pip 安装成功证据。
