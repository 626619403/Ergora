# S8：三个模板的 Agent 选型与解耦

基线 `3b52365`，工作分支 `feat/evolution-console`。用户要求按三个模板的方向调研 Agent，实现与模板解耦，并在研究后替换或补充现有实现，重点包括 ForgeKernel。冻结参考源码和合同保持可校验；本轮使用其真实消费者与证据接口，不另建开发生命周期。

## 实施边界

- 治理与大型开发模板只描述角色、能力、产物和验收。项目分别绑定 inspector、planner、implementer、reviewer；integrator / verifier 仍由可信执行器执行，不交给生成模型。
- 复用项目工具绑定、同一进程调用和正式 FileAdapter。添加显式启用的参考执行器桥接：继承现有阶段执行，替换模型调用与 Actor 身份；原安装、默认执行器及冻结模板不暗中改写。
- 首批 Agent：Codex 默认；Claude Code 可选；mini-swe-agent 补充实现；自定义 stage-json 命令提供明确的能力声明和结构输出。独立进程不等于 OS 隔离，保持当前容器 / 用户边界。
- 训练模板分别声明实验规划、性能分析和 kernel 生成。ForgeKernel 使用原生 new / run / status，以原生 campaign 为恢复身份，生成候选不等于 perfctl 可信门禁通过。先执行 CPU 的真实 dry-run；模型 / GPU 成效未实测则明确保留限制。
- CLI 与控制台展示同一角色 / 能力及实际可用性。复制模板时增加独立的 Agent 合同，不把具体厂商和本机路径写入模板正文。
