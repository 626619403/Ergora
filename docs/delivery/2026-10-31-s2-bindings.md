# S2：项目与实际工具绑定

基线为 S1 的包与冻结参考源码。用户要求不同层可选择实际工具，同时保持执行、工单和通信解耦。本切片在新 `ergora` 入口实现项目注册、带修订号的工具绑定、可用性检查及有界工具调用；不会修改既有 `agentflow` 运行时的配置或正式验收状态。

实现归属：`state.py` 负责用户持久目录中的 SQLite 文件和项目读取；`projects.py` 负责项目作用域与配置修订；`tools.py` 是具体工具目录和调用消费者；`processes.py` 负责无 shell 的 argv、超时和进程组清理，供 agent 和后续可信 evaluator 复用。CLI 为首个消费者，后续 Web 使用同一逻辑。默认数据目录遵循 XDG，亦可使用 `ERGORA_HOME` / `--home`，无私有状态进入源码库。

目前实现者和审查者可分别选择 Codex、Claude Code 或自有 argv 命令。Codex 使用 ephemeral 会话、按角色选择 sandbox；Claude 审查只暴露读取工具。用户须自行配置相应工具凭据；`doctor` 只证明可执行文件存在，不声称登录或模型效果通过。命令执行退出码、失败、超时、绑定修订和输出文件均保留。工具调用成功不产生六阶段正式验收。

记忆、优化、资料等层在相应切片具有真实消费者后才开放；不提前显示不可调用的选项。SQLite 作为文件基线无需额外服务，避免 CLI 与 Web 并发编辑 JSON 时丢失更新；冲突保存显式失败。

当前状态：已实现、已验证，独立审查待进行。wheel 非 editable 安装后，`tests/test_projects_tools.py` 4 项集成测试通过；联合 S1 / 原合同为 **56 passed, 36 subtests passed**。验收覆盖持久恢复、并发修订冲突、重复项目、未知配置拒绝、实际 argv/stdin/cwd、失败和超时留存。未运行真实 Codex / Claude 模型；使用其实际 `--help` 核对调用参数，认证与效果仍需目标工具用户验证。
