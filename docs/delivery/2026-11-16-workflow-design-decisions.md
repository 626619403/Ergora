# WA4：用户确认的设计关卡与实施顺序

2026-11-16。记录本次对话中用户对三项异步讨论的明确答复，关联[详细方案](../plans/2026-11-15-workflow-design-and-execution-evolution.md)。这份文档确定产品方向；它不是某个运行候选的批准记录，也不会替代原 actor／材料摘要／attempt／receipt 或授予执行权。

|决定|用户原答复|采用的规则|
|---|---|---|
|D1 适用范围|“采用建议范围”|框架开发、结构重构，以及算法、数据、权限或验收标准的重要变化，在新 profile 中强制完整设计讨论；普通小修复由项目规则决定。旧冻结任务与 profile 不被静默改变。|
|D2 必答与必要知识|“采用上述规则”|项目／模板规定最低必答项，任务负责人可追加；免答、降低要求或接受假设必须由有权负责人明确记录，不能由 Agent 自行跳过。|
|D3 决策与修订|“采用上述规则”|先由一个任务负责人决策；设计修改产生新 revision，重要接口、验收、权限、算法／数据或方向变化须重新批准；沉默不算批准。|
|D4 实施顺序|“采用建议顺序”|先设计与必要知识关卡，再可信脚本／测试节点；并行完成已在实施的训练循环；最后通用 Repeat 与混合工作流画布。|

后继先把 WA5a／b 拆成可验收的设计包、问题／答复、明确决定及原批准／work 投递门。采用现有 plan artifact、版本化 profile、原任务批准与 Temporal，不另建调度器或批准账本。先核真实调用与持久版本，再明确 schema、接口、恢复／迁移、最小反例和 CLI／页面交接；独立设计审后按片实施。可信检查和一般 Repeat 仍须各自的具体契约及真实验收，不能以本次选择声称已经支持。

当前 M5／原生依赖隔离与安装验收继续，不将这次产品决定解读为对训练质量、某个候选或外部写入的批准。实现、测试、独审与发布分别在所属交付记账；后续若改变上述产品取舍，应新增明确决定并保留本记录。
