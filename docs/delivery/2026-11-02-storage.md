## 已核实的起点和采用方案

现有基础 State 只有 projects / agent_runs，其他 14 表由七个领域模块 lazy 创建；总计 16 表、`PRAGMA user_version=0`，结构和合成数据已由 A2 固定。继续采用标准库 sqlite3、原表名/文档/查询与各领域事务，不加入 ORM 或万能 JSON repository。

R3.1 在存储边界串行初始化，迁移使用显式事务，不用会隐式提交的 executescript。迁移前从单独只读连接调用 SQLite backup，保存原库版本；任何 DDL / 版本提交失败均回滚。备份使用 `.part` 暂存并检查 integrity，关闭连接后才发布正式文件。初始化锁与 SQLite 写锁各负责新客户端串行化和数据库事务，连接每次核对支持版本。已有表结构不符合旧格式时明确拒绝，未知额外表/索引/触发器保留，不静默重建或丢弃。

旧 0.2.0 没有版本检查，仅 user_version 无法隔离它。已给已知表的 INSERT / UPDATE / DELETE 增加触发器，要求连接注册的 writer-schema 函数匹配版本；旧连接缺少此函数，其写操作会在 SQLite 拒绝，新连接注册当前版本。返回不匹配版本或 NULL 也拒绝。此保护针对旧二进制的已知数据库写路径，不是同用户恶意 SQL 的安全边界，也不能停止旧进程写文件或启动外部工作。升级前应停服务并对账在途工作。
