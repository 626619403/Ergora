## 阻塞发现

### DRD-1 / P1：预览、明确采用与最终检查尚未绑定同一完整候选

**位置：** r1 计划第 18、19、24 行；`src/ergora/definition_bundles.py:136`、`:146`、`:273`；`src/ergora/asset_trees.py:39`。

**触发与后果：** 当前 inspector 会因旧声明摘要与修改后字节不符而拒绝，不能直接把现有 `revise` 当作资源预览。r1 没有固定先修复哪些字段、返回哪份标准正文、在哪一步执行当前完整准入。更关键的是，仅在最终阶段重核“各声明资源”的摘要无法绑定普通未声明附件和独立文件执行位：CLI 预览附件 A，操作者接受后外部变更目录变成 B，声明资源摘要仍可全部正确，最终可能发布未接受的候选。最终结果“应该一致”还不是调用者可以检验的合同。

**最小纠正：** 沿原 `revise` 的可选资源参数固定一条明确预览路径：完整暂存并应用操作，按原算法更新且仅更新输入声明的 `sha256`/`digest`，由原序列化器写出建议正文后再计算候选身份。固定预览是否执行当前完整准入；优先复用现有完整准入并明确预览失败不发布，避免增加另一套放宽的 inspector。新增声明在不改 schema 的前提下，应明确使用合法占位摘要或其他唯一约定。

预览必须返回可下载的完整建议正文、差异和可携带的接受身份；检查/发布重新暂存并比较这个身份，不能自动修复调用者最终正文中的摘要。身份至少包含原算法的完整包 `digest`，并按 DRD-3 包含目录清单。接受后的任何正文、文件字节、执行位或目录变化使该接受结果失效。没有资源操作的 C3b 调用保持原行为。不需要持久化预览 token 或新服务端会话。

**验收出口：** 两类定义中，预览后的未声明二进制附件、声明文本执行位、正文或目录任一变化均被最终检查/发布拒绝；字节及目录相同的显式重试仍得到同一候选。预览不发布版本，最终准入不信任客户端摘要。

### DRD-2 / P1：文件操作和 CLI 外部目录仍存在多种不兼容解释

**位置：** r1 计划第 15–17、21、24 行；`src/ergora/definition_bundles.py:17`、`:110`；`src/ergora/cli.py:16`；`src/ergora/web.py:37`、`:230`。

**触发与后果：** “本地变更目录”没有固定其根如何映射到包路径，空目录如何表示，删除与执行位从哪里取得。一个 `references/a.bin` 既可能被解释为包根附件，也可能被解释为选中 Skill 下的文件；目录覆盖、文件/目录替换和大小写改名也没有唯一结果。CLI 与 HTTP 因而还不能证明携带“同一操作”。HTTP 使用 base64 与包内普通二进制是可行方向，但它们不是新声明资源 kind；现有 schema 只允许 instructions/context/skill。

**最小纠正：** 固定一种有限形状及其 CLI 映射，例如可选 `resource_changes` 仅含完整文件写入、明确文件删除、明确目录追加。每个文件只有包相对路径、完整字节及可选 `executable_bits`；HTTP base64 严格解码，库统一处理字节。CLI 可以使用操作清单加固定文件子目录，也可以使用包根 overlay，但须选定一种并写出一个完整例子；不得依据缺少文件推断删除，也不得依据上传源权限隐式改执行位。无需增加 move/copy/chmod 等通用 patch 指令。

同一合同须明确：

- 原标准 `agent.json`/`workflow.json` 的写入、删除及祖先路径冲突均拒绝；正文只走原入口。
- 删除对象必须是固定原包中的普通文件；缺失、目录删除、同路径写删、重复写入及文件/目录转换如何拒绝。目录重复追加和多个文件共享父目录应有唯一规则。
- 大小写冲突按原可移植路径规则处理，明确是否拒绝一次请求中的大小写改名；不能依赖宿主文件系统决定胜者。
- 原声明的删除必须由正文明确移除声明，否则原完整准入拒绝；普通附件不自动生成资源声明，预览不根据文件名猜 resource ID/kind。
- 执行位只允许 `0o111` 的位组合，省略时旧文件保持、新文件为零；完整 UTF-8 文本编辑与不解码的二进制上传分开。仅在新暂存树内处理只读文件/目录，并覆盖异常清理；不能把改文件权限推广为工具授权。
- HTTP 上限是实际请求字节 `4_000_000`，包含正文、base64 和操作清单；最终包仍为 `10_000_000` 字节、500 文件、500 目录、32 层，不能把增量大小代替最终包上限。大变更明确走 CLI，无需上传分片服务。

**验收出口：** 同一固定清单经 CLI 与 HTTP 得到同候选；链接/reparse/special-file、标准文件通道、冲突路径及超限均在发布前明确拒绝；原包、未改字节及执行位不变。

### DRD-3 / P1：空目录不参与旧摘要，现有对象复用会丢掉新候选目录差异

**位置：** r1 计划第 17、19、33 行；`src/ergora/asset_trees.py:44`；`src/ergora/definition_bundles.py:113`、`:156`、`:224`。

**触发与后果：** 两个候选的标准正文、文件字节和执行位完全相同，仅新增空目录不同，因此有同一 digest。原 `import_bundle` 在目标对象已存在时只执行 `_get`，随后按同内容重试成功；实际导出仍是先发布对象的目录树。只要求新版本号不能解决两个客户端为同一新目标版本选择不同空目录的场景。当前 `inspect_bundle` 还丢弃了 `inventory_tree` 返回的 directories，调用者无法核对此差别。

**最小纠正：** 保持旧摘要算法，把排序后的完整目录清单作为候选附加事实用于预览/接受/最终核对。在原 import 锁内检查同 digest 的现存对象目录清单是否与此次暂存一致；不同则明确冲突，不能声称相同重试成功，也不能补写旧对象。覆盖已索引对象及完整未引用对象。沿原树 inventory 暴露清单即可，不建立第二套内容身份算法。

**验收出口：** 两个只差空目录的同 digest 目标，第二次发布明确拒绝且原对象不变；相同目录重试成功；新空目录、原空目录及非空目录在成功新版本导出再导入后完整保持。

### DRD-4 / P1：摘要采用、资源缓冲与已应用历史尚无共同状态转换合同

**位置：** r1 计划第 18、32 行；r1 交付记录第 9–11 行；`src/ergora/data/console/definitions.js:21`、`:23`、`:43`、`:115`、`:193`、`:548`。

**触发与后果：** 现有 `pending`、持久缓冲、快照、undo/redo 和检查请求都只包含正文。r1 仅说采用建议正文到已应用快照；若操作字节未在同一步采用，上传→采用→撤销或刷新会出现正文摘要与文件内容来自不同状态。资源读取/预览还有独立异步回复，现有正文的防迟到规则不能通过一句“沿 C3b”证明它们不会覆盖较新上传、未应用资源文本或另一 home 的缓冲。

**最小纠正：** 在 D1 明确而无需实施页面：

- 工作缓冲保存未应用的完整资源文本/上传字节/操作；已应用快照保存完整标准正文及两格式原文、已应用操作字节和已接受候选身份。
- “采用资源摘要”在原文同步确认成功后，原子采用建议正文与同一预览所依据的操作字节，产生一份共同已应用历史。取消确认、预览失败或过期回复都保留原工作缓冲；未应用上传不能进入 undo 历史。
- 资源编辑、删除、读取完成和预览请求纳入同一 home/精确基准/编辑世代。采用或检查前只接受对应世代；原文件读取不得覆盖已有较新资源编辑。读到的窗口不可作为完整文件应用。
- undo/redo 恢复同一候选的正文和操作，不混合当前资源草稿；任何变化清除有效检查。刷新恢复保存的共同缓冲后重新建立历史并重新检查，不把旧检查或未应用资源标成已应用。
- 定义保存形状/版本兼容策略；损坏缓冲保留可下载原件。历史额度计入完整操作字节及其序列化开销；超限只裁剪完整历史快照，不能截断附件。quota 失败时下载包含工作缓冲中的全部正文和资源字节，不依赖短期 Blob URL 或文件选择器引用。

**验收出口：** 两类定义都覆盖上传/无效文本→预览→取消/采用→undo/redo→刷新，以及切 home、迟到读取/预览、quota 与未知发布重试；每一步能区分工作缓冲、已应用候选和实际发布回执，二进制不经文本替换解码。

### DRD-5 / P2：正文编辑后的接受身份失效规则不一致

**位置：** r2 计划第 18、32、42 行。

**场景：** 采用资源摘要后，再用原表单修改目标版本或说明。candidate digest 包含标准 JSON，因此旧 accepted_candidate 已过期；第 42 行却只要求操作改变时清掉它，与第 18 行“过期结果不启用检查/发布”不一致。最终库匹配会阻止错误发布，但页面仍可能把已过期接受当作有效，直到检查失败才暴露。

**最小纠正：** 明确任何已应用标准正文或资源操作变化都使 preview/accepted_candidate/check 失效，要求对新共同候选重新预览和明确采用。恢复历史仍可恢复当时匹配的三项，但检查必须重做；不能只为资源操作编辑增加失效规则。

### DRD-6 / P2：新增嵌套空目录尚未固定父目录创建行为

**位置：** r2 计划第 29、30 行。

**场景：** 原包没有 `new`，请求 `mkdir new/a/empty`。写文件明确自动建父目录，但 mkdir 未说明；如不建父目录，用户也不能通过同时声明 `mkdir new`、`mkdir new/a/empty` 绕过，因为祖先/后代操作被禁止，合法新空目录树因此没有可用表示。

**最小纠正：** 明确 mkdir 同样创建缺失的真实父目录，所有隐式父目录计入最终目录清单及边界；任何父路径是文件/大小写冲突则整体拒绝。无需放开有序操作或增加递归目录指令。

**r2 结论：** Standards 在设计所有者/复用范围仍通过；Spec 为 request changes，仅余 DRD-5/6 两处合同消歧。r2 已有可实施的主要形状，修正两处即可冻结；此判断没有运行实现、CLI/HTTP/浏览器或目录冲突复现。已做当前 `git diff --check`，通过；它不验证本片行为。
