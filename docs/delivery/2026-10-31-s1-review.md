## 首次发现

1. **高：当前项目可覆盖随包的合同编译器。** 位置：`src/ergora/reference.py:54`、`:57`。原实现设置 `PYTHONPATH` 后运行 `python -m dev_platform.portable`，但 Python 仍优先搜索调用者当前目录。参考 `dev_platform` 是 namespace 包，项目中的同名普通包会优先命中。在临时目录建立无害的 `dev_platform/{__init__,portable}.py` 后，`python -m ergora workflow --help` 和安装后的 `ergora workflow --help` 均执行该夹具，打印 `LOCAL_COMPILER_SELECTED`，返回 73，而非冻结编译器。结果是合同编译可被无关项目内容改变，破坏原合同入口的身份边界。最小修复：排除 cwd 与 site-packages 的导入干扰，例如对这个仅依赖标准库的子进程使用 `-P -S` 和固定 `PYTHONPATH`；保留调用者 cwd，使相对合同路径继续按用户目录解释，并为同名包碰撞增加回归。置信度 100。

2. **中：wheel 将测试字节码当作冻结资源打包。** 位置：`pyproject.toml:25`。`data/**/*` 会包含源码树里已被 `.gitignore` 忽略的 `__pycache__`；`.gitignore` 不约束这项 setuptools 显式配置。首次实际 wheel 和非 editable 安装均有 289 个 reference 文件：283 个公开原文件，加 `dev_platform` 下 4 个和 `tests` 下 2 个 `.pyc`。283 个原文件没有缺失或内容差异，但产物混入与构建机器及先前测试有关的缓存。`reference.verify()` 只逐项检查清单，因此仍返回 PASS。最小修复：在 package-data 中显式排除 `__pycache__`、`.pyc/.pyo`，清理旧构建暂存后重建；直接核对 wheel 内 reference 文件集合恰好等于清单，并核对每项摘要。置信度 100。
