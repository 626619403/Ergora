## Findings

### RDE-D1 / P1：第二轮预览可能丢掉已采用的资源操作

- **位置：** r1 页面计划第 17–19 行；邻接实现为 `definition_bundles.py` 第 420–428 行。
- **可达场景：** 固定原包有普通未声明附件 `a.bin`、`b.bin`。先暂存 `write a.bin = A1`，预览并采用；第 19 行会清工作操作，已采用 `resourceChanges` 为 A。再暂存 `write b.bin = B1`，第 17 行只描述将其加入工作 `resourceBuffer`；第 18 行有此缓冲时以它替代已采用操作。D2 每次重新 `export` 固定旧包，再应用所传操作；因此第二轮只有 B 时，候选中的 `a.bin` 回到原字节 A0。普通附件没有声明摘要阻止这一候选，第二次预览 / 采用 / 检查 / 发布均可成功，且第 19 行会将已采用操作换成 B。
- **后果：** 操作者没有明确撤销 A，却在继续编辑 B 时丢失 A。相同问题也影响先前 delete / mkdir；若 A 是新声明文件，则可能表现为第二次预览无法通过，而非静默回退。
- **最小纠正：** 定义 `resourceBuffer` 为相对固定原包的**完整工作操作集合**。首次编辑从已采用 `resourceChanges` 深拷贝，再沿现有精确路径替换 / 编辑 / 移除；`null` 表示无未应用操作，显式空集合表示操作者明确去掉全部操作，不能用真假值回退。放弃工作集合恢复已采用值；成功采用才原子替换正文、完整操作与接受身份并清缓冲。大小写、祖先 / 后代冲突继续交 D2，不增加树合并算法。
- **验收出口：** 两类页面都覆盖 A 采用→追加 B→第二次采用→check / publish，保住 A 和 B；同路径替换、明确移除旧操作、空集合与放弃也按上述合同区分，undo / redo 和刷新保留同一完整集合。

### RDE-D2 / P2：单文件上限和请求拒绝不能限制活跃资源缓冲的累计分配

- **位置：** r1 页面计划第 16–17、22–23 行；原合同 `definition-resources.md` 第 30 行限定操作最多 1500 项、写字节总量 10,000,000。
- **可达场景：** 每次上传都小于单文件 10MB，但连续对不同路径暂存。r1 第 17 行会持续保留完整 base64；第 22 行的总量校验仅写在恢复分支，第 23 行的 4MB 检查发生在组成 HTTP 请求时。即使只暂存两个各 9MB 的文件，也已超过共同操作总量；继续添加仍没有活跃集合上限。checkpoint / 下载的 JSON 序列化还会复制这些字符串。sessionStorage quota 报错只表示无法缓存，不能释放或限制已保留的内存。
- **后果：** 通过有限的单次上传反复累积无界工作字节；可能先发生序列化失败、页面卡顿或进程内存压力，当前未缓存编辑也因此面临丢失。最终 HTTP / 库的可见拒绝发生得太晚。
- **最小纠正：** 在读取 / 编码并把新字节保留进完整工作集合前，按候选替换后的集合核操作数及 decoded 写字节总量，沿原 1500 项 / 10,000,000 字节。精确路径替换应扣除旧项；上传用 `File.size` 先核，文本沿完整 UTF-8 字节核，不截断。超限保留此前集合和已有草稿并提示 CLI；采用、恢复和历史消费同一受限形状。这是传输分配预算，完整路径 / 树 / 最终包准入继续只由原库负责。
- **验收出口：** 用小型或合成大小的浏览器场景证明累计超限在保留前拒绝、精确边界有效、替换不误算重复字节、原缓冲可完整下载；不需要 OOM 实验或重复 D2 整组测试。

## 已核合同与限制

- 预览只保留固定请求和回执，不改变已应用三项；采用前沿原转换 interface 生成两格式，检查 home / key / 基准 / 世代，取消同步或异步期间新编辑均保留原缓冲。计划对原子性已有明确要求。
- 文件读取核各页身份 / 偏移 / 字节数，完整重建后才编辑或下载；严格 UTF-8、BOM 与 surrogate 约束、二进制完整字节、执行位和标准 JSON 单入口均与 D1 / D2 一致。尚无产品代码，DOM 文本控件往返和大文件实际分配仍需 E3 验收，不能据设计推定通过。
- 任意正文 / 文件 / 操作变化清 check / preview / 接受身份；有未应用缓冲时禁检查 / 发布旧快照；请求使用固定已应用值，迟到发布回执只记原发布结果，不能替换较新编辑。历史共同恢复正文 / 操作 / 身份并重新 check，未应用原文不进入已应用历史，保住 C3b S5 合同。
- checkpoint v2 与明确旧 v1 形状、无效缓存原件下载、重新核两种已应用正文、preview / check 不持久复用、50 份 / 4MiB 历史计入资源序列化字节、单份超限保当前及 quota 提示均有设计出口。下载准确区分完整编辑缓冲与不含原包的独立包。
- 未发现本片需要改写祖先材料 / 权限编译、底层摘要或发布 owner 的依据。原 D2 窗口每页会核历史完整包和文件，整文件读取的实际耗时需按 E3 所测范围报告；本审没有进行最大包容量或性能验收。

实际检查为只读源码 / 材料核对、基线 / 分支 / 状态检查、SHA256 与引用静态检查；私有原件在 `ac5-definition-resource-editor/design-r1/independent/`。**没有运行产品测试、浏览器、模型、服务、安装、提交 / 推送或外部请求。** 两项 finding 是按固定设计和真实调用链推导的可达合同问题，不冒称已运行尚不存在的 D3 实现。下一步先修订并复核这两项设计，再在 D2 精确交付终结后进入 E1 / E2。
