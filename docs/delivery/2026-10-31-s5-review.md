### 1. High：调度 ID 的拼接歧义允许另一个项目操作已有计划

### 2. High：自动重定向在限额循环外整体读取响应正文

- 位置：[research.py:170](../../src/ergora/research.py#L170)、[research.py:176](../../src/ergora/research.py#L176) 和 [research.py:188](../../src/ergora/research.py#L188)。
- 场景：指定来源返回 302，重定向正文很大，最终页面很小；为整个任务配置 10 字节预算。
- 独立证据：本地 HTTP 反例的 302 正文为 100000 字节，最终正文为 2 字节。研究任务仍 `succeeded`，保存的 `bytes=2`。已核对当前 Python 标准库：继承的 `HTTPRedirectHandler.http_error_302` 在跟随新地址前执行无参数 `fp.read()`，整段正文既不经过外层 `check()`，也不计入 `document["bytes"]`。
- 影响：一份普通重定向响应可以绕过全任务字节预算，并在内存中整体分配任意大的正文；持续触发时也绕过已记录成本和部分取消检查。重定向地址仍受私网检查，不能补足响应正文的资源限制。
- 最小修复：显式处理重定向状态，在验证下一地址后关闭当前响应，避免无必要的整体排空；若需要读取，则走同一剩余字节、deadline、取消及 checkpoint 路径。保留有限跳转次数并覆盖各支持的重定向码。增加“大重定向正文、小最终页”的回归，保证不会在限额外整体读取。
- 判定：CONFIRMED；置信度 99。

### 3. Medium：HTTP 协议断流异常逃逸，持久任务仍显示 running

- 位置：[research.py:195](../../src/ergora/research.py#L195)，终态捕获位于 [research.py:229](../../src/ergora/research.py#L229)。
- 场景：来源采用 chunked transfer，宣称一个 16 字节 chunk，却只发送 `short` 后断开连接。
- 独立证据：本地真实 HTTP 反例从 `research.run` 抛出 `http.client.IncompleteRead`；重新读取持久记录仍为 `status=running`。它不属于现有的 ValueError / OSError / URLError 捕获，因此没有 finished 或失败说明。
- 影响：常见的代理或来源中途断流不能成为可见失败终态；CLI traceback、界面和 Temporal 看到的本地研究状态不一致，重试耗尽后记录仍可能假装运行。

- 判定：CONFIRMED；置信度 99。

### 4. Medium：快照写入中断后，恢复任务可成功但候选永久无法审阅

### 5. Medium：响应头阶段没有总 deadline，socket 超时不能保证任务时间预算

- 位置：[research.py:184](../../src/ergora/research.py#L184) 和 [research.py:188](../../src/ergora/research.py#L188)；总预算检查只包围这些阻塞操作。
- 场景：来源每隔 0.4 秒发送一行合法响应头，直到 2 秒后才结束头部；任务 `timeout=1`。每次底层读取均能在 socket 超时前收到数据。
- 独立证据：该轻量本地反例实际等待 **2.01 秒**，才返回 `timed_out`，正文计数为零。阻塞于 `opener.open` 时不会执行 `check()`；每次成功 recv 又避免了 socket 超时。持续合法头部可以远超声明的秒数。DNS 解析同样位于总检查之间，不能由传给 `open` 的 socket timeout 直接约束。
- 影响：这超出文档声明的“等待当前 socket 超时”余量；时间预算与取消确认都可被持续响应头拖延。若 worker 在首次 checkpoint 前退出，消耗的这段时间也不会留在累计 elapsed_seconds 中。
- 最小修复：将 DNS、连接、响应头和正文读取置于可中断的总 deadline 下，取消与超时须能停止阻塞中的传输，并持久保存真实终态；若采用独立受控进程，应在到期时终止并对账，而不是遗留后台抓取。覆盖持续响应头、取消时仍在响应头阶段、首次正文前中断恢复的预算回归。
- 判定：CONFIRMED；置信度 98。
