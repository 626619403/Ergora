## R1 — preserve existing manual-job recovery when intent classification fails

**P2, requirement compliance.** [reference_training_worker.py](../../src/ergora/reference_training_worker.py:46), especially the unconditional read/decode at lines 46–51 before the original `super().create_job_if_absent` call.

A native job may already exist while its old submission intent is unreadable, partial or malformed. The original adapter deliberately returns the same existing job from the native registry algorithm without reauthorizing its creation: its extra budget/source checks run only when the locked native lookup returns no job. The new eager classifier reads and decodes the intent first, catches only `FileNotFoundError`, and therefore rejects that existing-job recovery on a JSON/read failure before the original locked lookup can return it. Returning an existing job needs no new creation grant. This adds a dependency to the original manual retry/recovery path and can fail an otherwise idempotent create activity instead of returning its already-created job.

The reviewer reproduced the difference with the actual native create implementation, identical valid manifest/config/job inputs, and a private copy of retained runtime/config files. With the private submission intent set to partial JSON, the baseline worker returned `local-perf-alpha`; the candidate raised `JSONDecodeError: Expecting value: line 1 column 15 (char 14)`. No original run artifacts, product files or live process were modified. Reproducer and result are `product-audit/manual-existing-probe-r1.py` and `product-audit/manual-existing-probe-r1.json`. Baseline worker SHA256 is `067d0788c9da1700a6c17a68a7bfe605e65552f9552a928945a39ac3e85a2895`; candidate worker SHA256 is `8366a91a854af6d40682ceb515bd6c576ad8e63bcdd047262607b6b32e0a3f23`.

The smallest correction is to let an unclassifiable intent reach the original native existing-job path without treating the classification failure as permission to create. When the original locked lookup returns `None`, the existing `budget_for`/source validation must still expose the same malformed/missing/unreadable intent and reject new creation. A readable controller binding must continue to acquire the parent permit and verify fixed parent history before entering the native create algorithm. Verify both outcomes at the existing native-create seam: same existing job returned, absent job still denied and no new request written. Do not add a second creation algorithm or weaken the complete source validation for new jobs.
