# S5：有界资料研究与可选持久调度

目标是主动观察指定资料的新版本，保存来源快照并提出可审阅的更新，不自动将网页内容变成有效记忆或 skill。本切片先实现有界 URL 抓取，保留任务身份、来源内容 SHA、相同内容去重、字节/时间/来源数量预算、失败和取消；随后复用 Temporal Schedule 做可选持久触发，不写第二套常驻调度器。

来源只接受操作者明确配置的 HTTP(S) URL。页面内容视为资料，不执行其中指令、脚本或工具。默认拒绝私网地址，可信内网资料须显式选择；重定向也按同一规则核对。本地开发入口无工单或聊天依赖，研究结果仅是候选，操作者可选择带来源写入记忆。

实现归属计划：`research.py` 管理抓取、快照与候选状态；`scheduling.py` 只适配 Temporal workflow/activity/schedule。CLI 与 Web 都调用研究逻辑。运行状态归私有持久目录，公开文档记录验证范围。当前开始实现，测试与独立审查待进行。

已实现上述归属及 `research` CLI，工具层增加 urls / manual / temporal 的真实消费者。任务 ID 输入冻结、文件锁避免并行重复、完成来源逐项 checkpoint；保留累计字节与 elapsed_seconds。取消作为独立请求字段，不提前伪造终态。来源 snapshot SHA 去重、源版本变化产生候选，候选审阅有修订冲突检查。默认私网地址与重定向检查不宣称网络强隔离。

验证：实际 HTTP fixture 的快照/去重/身份/作用域/审阅、字节预算/私网拒绝/重定向、取消确认三项通过。安装真实 `temporalio==1.34.0`，在独立 Temporal CLI 1.9.1（Server 1.32.0）开发服务上运行 `ERGORA_TEMPORAL_TEST_ADDRESS=127.0.0.1:17333 .venv-dev/bin/python -m pytest -q tests/test_research.py`：**4 passed**，包括实际暂停 Schedule、trigger、worker/workflow/activity、resume/pause/delete。未触碰参考平台的既有服务。

持久性追加验收：使用 SQLite-backed 开发服务创建暂停 Schedule，关闭服务并用同一 DB 重启，确认 Schedule 仍 paused、actions=0，再删除验收计划。**通过**。运行 fixture 状态在 ignored build 目录，属于可清理验收数据；报告和实现保存在仓库持久文档/源码中。S5 已实现并验证，独立审查待进行。

未验证：生产 Temporal 认证/HA、互联网资料结论质量、DNS 重绑定隔离、模型主动搜索或常驻无预算探索。运行内容从不自动变成有效记忆或 skill，按计划先以可审阅资料候选收敛。

## 初审修复与回归

[初审](2026-10-31-s5-review.md) 的 6 项发现均已在实现中处理：Schedule 改用项目和名称规则均不允许的冒号分隔；创建与直接观察复用数量/唯一性/预算校验。网络抓取在 `spawn` 子进程中运行，父进程按总 deadline 和取消请求终止并回收，DNS、响应头和正文都在该边界内。重定向手动校验后关闭，不排空无用正文；HTTP 协议断流以失败结果返回。正文通过独立临时文件逐步计费，完整抓取后原子替换 SHA 快照，同时修复已损坏的同 SHA 对象。

研究执行每秒保存时间进度；控制进程异常退出时，恢复对最后 checkpoint 后无法证明的网络运行时间保守计费，最多耗尽剩余预算。各次传输使用独立临时名；Linux 父进程死亡信号约束网络子进程生命周期。取消在响应头阶段也由父进程确认并回收；终态保留实际已写出的字节。

独立复核又复现了“旧传输未终止而恢复再次花费剩余字节”和 Content-Length 正文提前 EOF 的问题。现在未确认结束的传输将其余字节记为 `reserved_bytes`，不会据单次文件 stat 重复开销；研究会可见失败，操作者需显式新建有新预算的任务。只有已确认结束的抓取才能恢复后续原子发布及 checkpoint。已知长度正文 EOF 后核对剩余长度，拒绝不完整快照。已追加真实控制进程 SIGKILL / 立即恢复和短 Content-Length 回归。
