## 本片合同

新增显式task-mcp单叶调用模式，默认text-only保持。使用官方SDK stdio，不手写JSON-RPC或引入网关。沿原完整已核输入和当前准入，原生backend继续只负责各自配置。祖先与自身instructions/context/Skill指令保持完整内联；仅选中叶子的全部声明资源含Skill附件通过read/list可达，兄弟、未声明文件及输入包索引不可达。首片不开放实时workspace、写、shell、工具网络或任意外部server，也不向v1定义/schema暗加MCP字段。

范围冻结为有界、内容定址的独立scope；server在启动时校验并将允许内容装入内存，工具仅查虚拟URI表，不接触用户传入的宿主路径。生成时从固定定义按已核files身份读取，只选声明的文件/Skill目录，保存原全部来源。对路径与普通文件/链接的实际检查归资源所有者。Linux先实现不会跟随链接的descriptor读取；其他平台不能声称同等路径保证，支持矩阵待实测决定，原Windows功能保持。

MCP server无服务凭据，实际启动前清理继承凭据/Python注入；推理认证留原生后端。使用官方client模型前核初始化与工具清单，另保存原生调用自己的服务连接审计；后者缺失时即使最终JSON成功也失败。预检、实际连接与工具成功分别记账。进程取消/超时沿原生命周期，不留后台服务；本模式不提供OS隔离。

## 资源接口决策

scope持有选中资源的原始字节、SHA256与完整来源，独立于活动定义库和workspace。总原始内容最多10MB/500文件，序列化scope额外有限额；超限拒绝，不删减祖先。Skill只开放其固定完整目录；普通正文只开放声明文件。server启动一次核scope摘要/版本/schema及每个文件摘要后只读内存，随后任意list/read字符串都不能成为宿主open参数。此选择避免运行时路径替换竞态，也能在原输入删除后继续核本次投影。

read按字节分页，上限64KiB并提供全文件SHA/大小/offset/next_offset；可完整UTF-8解码的块返回文本，二进制或跨编码边界返回明确base64。list仅列已授权虚拟URI、摘要和来源，分页最多100条，不扫描宿主目录。非法便携路径、未知URI或越界offset明确错误；原生MCP资源/prompt不另注册旁路。

预检使用单独回执路径；实际native服务通过SDK middleware记录initialize、tools/list、工具名称/结果，不记录凭据或内容。实际调用缺对应scope的官方SDK有效连接/精确两工具清单时，原始模型回答可保存但本次调用失败，不以预检成功替代。服务仅由原生CLI为本次调用拉起，进程清理仍由原process owner负责。
