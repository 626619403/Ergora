# S3：项目长期记忆与 ReMe 检索投影

用户要求长久保存信息、按层选择真实工具；计划要求来源、项目范围、修订、纠错、删除、恢复和可选 ReMe 接入。S3 在 `memory.py` 负责这些语义，CLI 和后续 Web 共享调用；`tools.py` 只验证绑定和展示支持能力。默认 SQLite 文件基线不需要新依赖；它与项目配置使用同一持久目录，方便一致备份和并发修订控制。

每条记忆有 project、UUID、revision、text、source.uri、source.revision、observed 和 status。纠错保留旧版本，检索只返回当前有效版本；恢复历史修订产生新修订。删除擦除逻辑历史的正文与来源并保留 tombstone，不能从应用历史恢复删除正文；这不清理用户保存的独立备份。复制无活动写入的完整 state 目录可以恢复；运行中备份应先停止所有写入进程。

ReMe 接入使用 HTTP `POST /write`、`/delete`、`/search`，不复制或导入其引擎。依据官方提交 `1e51e0dc1b1effe60f7ee425298f3b6f8ef4cbd9`（源码版本 `0.4.2.2`）的 `docs/en/services.md`、`memory_search.md`、`reme/steps/{file_io,index}/` 与默认 job 配置。源码链接见 [接入手册](../INTEGRATIONS.md)。

本地 SQLite 是事实来源；ReMe 保存 `digest/ergora/<project>/<memory>.md` 检索投影。远程返回必须命中本项目已登记路径，展示内容重新从本地有效记录读取，防止其他项目及过期正文进入结果。写入/删除失败明确报错，不自动换后端。同步是文件确认，ReMe 索引可见性由其 watcher 决定。保存后切换端点或切回本地，旧端点仍登记在 mirror 中；显式同步会对已登记投影传播更新/删除。
