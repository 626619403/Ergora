## 本节点范围与验收

按 ADR 0001 接入 `jsonschema==4.24.0` / Draft 2020-12。组件绑定使用 R1 的同一份 configuration，Agent 阶段结果使用现有生成 schema；评价输入和 evaluator 结果集中到随包 schema。共享校验返回字段路径，不转换输入、不注入默认值。保留项目修订、角色能力覆盖、URL / 绝对路径、评价 case 的安全 ID / 唯一性 / 三个 split、可信文件身份和评分门禁等业务规则。

明确 Python strict integer 与 bool / finite number 的实际语义；不让 JSON Schema 将 `1.0` 当作原先要求严格 int 的参数。评价旧版本号检查原为 `== 1`，本节点保留它实际接受的 `1` / `1.0` / `true`，不把历史宽松行为偷换成新版本迁移；其他版本仍拒绝。结构描述版本与协议、持久文档版本分开。冻结 reference 合同、DB、摘要编码和已有合法语义保持；不把 Web 的 Pydantic DTO 提升为核心依赖。

验收：全部绑定矩阵和 A2 固定身份；CLI / Web 的相同绑定与评价输入得出相同业务结论；未知/额外字段、未知版本、BOM / UTF-8、整数 / bool / 非有限值、Agent / evaluator 结果拒绝路径；基础 wheel 无 Web 依赖仍可运行；完整 Linux、两 OS CI、独立审查。真实模型/GPU及外部服务效果不在本节点。

初审提交 `defda32aed4811e7bcf77bab531d5c6f566da0fc` 的 [CI 41334860593](https://github.com/626619403/Ergora/actions/runs/41334860593) 页面已实际核对为 Failure，精确提交一致；Windows 的研究请求期限、取消及控制器退出四项失败，表现为启动/到达本地 HTTP 服务耗时。相关源与测试断言未改，尚未证实原因，不以“与本次无关”关闭失败，也不放宽原计时约束；下一候选须重新核对两 OS 结果。

[独立初审](2026-11-02-schemas-review.md) 发现 P1：`integer` 接受巨大 Python int，而 `number` 拒绝它；jsonschema 的 minimum / maximum 先询问 number，导致 mini step_limit 和 evaluator timeout_seconds 的正负 `10**1000` 均绕过上下界。修复让两种类型的有限数判定一致；这两个整数配置本来都有小范围上限，合法输入集合保持。新增正负绑定与完整注册回归，没有改固定身份或下游超时规则。
